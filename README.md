# 项目助理 · 本地工作助理

**Tauri 2 + Rust 核心 + React / TypeScript + SQLite**。资料、记忆、任务、进展、日报和备份保存在本机。桌面通过 IPC 调用 Rust，无需自建服务器。开启云端 AI 后，选中的资料文本会发送给你配置的模型服务。

## 当前版本：0.3.0

日常从「今天」进入。首页按项目经理的四个问题组织：今天要推进哪些个人工作、哪些事项需要拍板或跟进、项目交付是否有风险、聊天与资料带来了什么变化。默认展示前三项个人工作，带上阻塞、逾期或排期理由；项目优先展示交付风险、已完成任务数和最近的未完成里程碑。顶部只保留「今天、项目、资料」，其他工作工具按需展开。

接入飞书群聊和文档并开启同步、配置模型和自动整理后，已有后台流程会持续采集与整理；已确认数据变化自动反映到首页，切回窗口时也会检查更新。原文、待确认内容和正式事实分别标记，冲突与歧义保留人工核对。同步未开启、整理暂停或读取失败会显示状态。个人工作沿用明确的「我的执行」分类；任务完成比例表示任务计数，不等同于项目的实际交付百分比。

1. 创建项目，导入资料，核对带原文依据的记忆和任务候选。AI 提取需自行配置模型；人工整理与以下工作流程无需模型密钥。
2. 在“任务”新建事项，选择“我的执行”或“跟进他人交付”，设置负责人、优先级、计划日期和截止日期；也可从已确认记忆创建任务，固定对应的记忆版本和依据。
3. 在“每日清单”按日期和项目查看当天安排、未结和逾期事项。无日期的事项保留在任务池，可再加入指定日期。
4. 打开任务记录进度、状态和说明。每次修改保存业务日期、修改前后状态及版本，冲突时重新加载核对；来源资料与人工进展分别保留。
5. 在“日报”选择日期与项目，本地整理当天事件、阻塞与后续安排。完成后重新打开的事项不会列为当天完成；其他日期的完成事项不会冒充当天成果。
6. 核对日报依据，编辑后保存新版本，可查看旧版本、复制或导出 Markdown。日报不自动发送给他人。

清单和日报按所选日期的历史状态生成，之后的改名、进度或重新打开操作不会污染历史快照。工作日期不能早于该任务最后一条进展日期；录入时间另行保留。日报使用本地规则整理已记录的事实，当前不调用模型润色。

AI 任务候选可以确认成新任务，也可以关联同项目的已有任务。关联时明确展示状态和进度的前后比较，确认后才更新，保留原有任务名称、负责人及排期。AI 不自行识别“我”，个人执行与跟进角色由用户选择。

## 日常使用完善（schema 12）

- **草稿恢复**：任务表单、日报、周报、会议在编辑时暂存到本机，切页或重启后可继续；正式保存清理对应草稿。周报与会议按编辑版本保留草稿，旧版可从历史选择恢复查看。
- **待处理**：集中查看到期工作记忆、待确认候选和需澄清内容，按项目和来源筛选；复核保存新的修订和依据。
- **会话与收藏**：项目问答保存本地会话、问题、回答、引用和用量；支持收藏及明确对象的追问，历史答案不会作为新事实。
- **搜索与批量操作**：Ctrl/Cmd K 搜索项目、原文、记忆、任务、日报、周报、会议和管理记录；资料最多50份批量导入，任务最多100项原子批量排期。
- **归档与版本**：设置与工具内可预览影响、归档/恢复项目、停用/恢复资料、关联新版。旧资料和引用保留，停用资料不再参与当前记忆问答。
- **桌面运行与保护**：可选择托盘后台、登录启动、合并系统提醒及免打扰；自动备份只按保留策略清理自动副本。恢复后这些自动行为暂停。
- **质量与费用**：本地人工事实标注、JSON导入导出、漏提/条件/替代计分；人工清单未完成时不宣称召回率。问答显示实际请求数与提供方报告tokens，缺失用量保留为未知。

页面按需加载，任务/资料列表与全局搜索分页；后台先读取轻量变化标识，有变化再刷新工作区。功能与验证状态见[日常使用交付记录](docs/daily-use-upgrade.md)，打包、签名、更新和回滚见[桌面发布说明](docs/desktop-release.md)。真实业务标注语料目前未提供，业务准确率待验收。

## 第二阶段：自动提取候选

1. 打开“模型设置”。DeepSeek 预设为 `https://api.deepseek.com`、`deepseek-flash`、JSON 对象输出，也可配置其他兼容 API 或本机 Ollama。
2. 在应用中输入自己的 API Key 并保存。点击“测试连接”，使用一段内置合成文字验证认证、模型和结构化输出，不发送项目资料。
3. 核对服务地址，勾选同意发送资料并开启“新资料自动提取”。设置影响以后导入的资料；已有资料需要逐份点击“开始提取”。
4. 导入文字、Markdown、DOCX 或可提取文字的 PDF。原文解析完成后，独立后台任务调用模型；界面显示排队、批次进度及结果。
5. 成功批次会逐批保存待确认候选，不必等整篇处理完。核对内容与原文引用后可编辑、忽略或确认。**手动导入的候选只有用户确认才创建正式记忆**。主体、角色、条件或有效期校验失败的内容显示在“组织范围待审核”，须修正并填写审核原因，生成候选后再确认；无效主题标签单独隔离，保留原值和原因。引用逐字匹配不代表语义必然正确。
6. 提取失败可恢复未完成批次，运行中可取消。已保存候选继续保留，界面显示只覆盖部分原文；同一资料、模型配置和提示版本下，已成功批次不重复调用。取消后不会写入迟到结果；已发送的请求可能已经产生费用。网络、认证、限流等错误不自动重试；容量错误可以在任务预算内拆分小批次。

记忆提取类型：项目事实、决策、需求、风险；同次提取可生成独立的任务候选。相对时间保留原文表达，等待用户核定日期。人工整理入口仍然可用。飞书个人账号代答见下文；向量语义检索尚未实现。飞书自动采集、空闲比较与冲突确认见下文。

## 自动采集与记忆整理

侧栏“记忆中心”可以指定飞书群与 docx / wiki 文档，为每个来源绑定项目并启用增量同步。采集保留原文和版本，空闲时提取并比较该项目当前记忆；独立新事实可按设置自动加入，完全相同的内容合并依据，冲突、更新和不确定内容等待用户确认。旧版本和原文依据保留。

默认空闲 120 秒开始，每天最多 100 次整理模型请求。应用需保持运行并完成个人授权和模型配置；真实飞书接入需要企业批准相应读取权限。手动导入的候选仍需确认。恢复备份后同步与整理暂停。

详细配置、获取范围、更新规则和运行边界见[记忆系统说明](docs/memory-system.md)。

## 项目简报与记忆质量反馈

- **项目总览 → 项目工作简报**：本地生成目标、进展、已确认决策、阻塞、后续任务和最近记录，保留任务、记忆及原文入口。记录变化后显示过期提示，点击“更新简报”重新整理。
- **项目记忆 → 修订**：填写修订理由，可附一个真实问题；旧内容、新内容、版本和问题一并保存。在 **记忆中心 → 质量反馈** 检查这些问题能否召回当前修订。
- **记忆中心 → 质量反馈**：对未经人工编辑的 AI 记忆/任务候选核对原文，记录正确、负责人错误、日期错误、状态错误、依据不足等结论；也可对资料记录漏提。统计只代表已标注样本。
- **项目问答 → 个人偏好**：明确填写职责、回答详略、日报格式和跟进措辞，可随时编辑或清空。职责仅供模型组织回答参考，不自动识别“我”；日报格式影响之后生成的日报。

问答按问题意图优先选择进展、决策、原因、排期或负责人相关记录。简报是派生快照，不写成新的项目事实；纠错检索检查不等于模型回答或提取准确率。新数据随 schema 12 工作区备份保存，旧工作区自动迁移。

当前采用无向量检索：FTS5候选检索配合BM25排序，组织标签按修订保留主体、事项、角色、条件与有效期。模型按“结论—引用—当前正文锚点”输出，支持部分回答并单列未知信息；普通问题收紧上下文，复杂结论按需核验。桌面仍支持明确任务的负责人/截止日期零模型调用；最多5次请求，共用超时并记录实际usage。详见[当前记忆架构](docs/memory-system.md)。

生成与语义核验模型只接收白名单投影后的当前参考正文、标识和组织信息；原始引文及完整记录保留给界面和审计。已通过全部引用、锚点和字段校验的回答若同时标为`answered`并带有合法`unknowns`，会规范为`partial`，保留已知与未知内容。

## 飞书个人账号代答

在“飞书个人助理”保存应用凭据并完成个人授权，将飞书群绑定到本地项目后开启自动回复。成员在群内 @你，助理复用桌面项目问答，读取绑定项目的任务、最新进展、风险、里程碑、管理记录及已确认记忆，并用你的账号回复原消息及依据。不会读取其他项目；发送前再次核对当前记录。部分信息缺失会明确说明，所问内容均无依据时保留跳过记录。

需要飞书应用权限获批、个人 OAuth 授权及可用模型配置。无需成员 @机器人；桌面程序需保持运行，消息搜索存在索引和轮询延迟。首次启用从当前时间开始，消息 ID 去重记录独立保存，工作区还原后自动回复暂停。凭据和令牌不进项目备份。

配置步骤、权限、恢复行为与验证方法见[飞书个人账号助理](docs/feishu-personal-assistant.md)。

桌面与飞书的统一问答接口、12类项目经理问题及真实模型验证见[项目经理统一问答与验证](docs/project-questions.md)。

## 每日容量与排期

在每日清单填写当天可用时间及会议预留，再整理飞书信息、项目记忆和现有任务，核对归并、依赖、阻塞与估时。按容量生成带理由的试排，可调整后重新计算；确认才会改动任务日期与顺序。次日容量由你重新填写。见[每日排期说明](docs/daily-planning.md)。

## 项目总览、主动跟进与统一问答

- **项目总览**：维护项目目标、状态和目标日期；创建里程碑，核对原定日期、当前预计日期及关联任务。全部项目可统一查看阻塞、逾期和延期依据；关联任务没有全部完成时，不能完成里程碑。
- **提醒与跟进**：根据截止日期、最近进展及约定跟进日生成提醒。应用运行时每分钟自动检查，并在其他页面显示跟进提示；可以记录跟进、约定下一次日期、暂缓提醒和复制催办草稿。
- **项目问答**：联合当前任务进展、依赖、已确认排期、项目记忆、里程碑和日报回答问题，并附可核对的依据。默认使用本地规则；可主动选择已配置且获准读取资料的模型。

新数据随工作区备份保存，旧工作区自动迁移。检查日期用于评估当前记录，不代表还原该日期的完整项目历史。提醒需要应用保持运行，可通过应用内横幅、数量徽标和可选系统通知提示；催办草稿由你复制使用。原飞书代答仍使用原有的项目记忆范围。详见[交付与跟进说明](docs/p0-delivery.md)。

## 风险决策、变更验收、周报与会议

侧栏“项目管理”提供三个工作区：

- **风险、问题与决策**：记录责任人、影响、处理方案、期限和复查日期，保存进展与版本；关闭需填写结果和原因，决策还需记录拍板人与结论。可从已确认记忆起草，确认前不创建正式事项。
- **需求变更与验收**：保存变更前后、影响评估、审批与实施记录；修改内容后重新审批。交付物使用独立验收标准与核验依据，全部通过且实际交付完成后才能验收通过，目标更新会提示重新复核。
- **周报与会议准备**：按日期区间生成有依据的本地周报，编辑保留新版本，可复制或导出 Markdown；会议可生成议程和会前简报、记录纪要与行动项，行动项明确确认后才创建任务。

管理关注进入项目总览、应用内提醒和统一问答，引用可打开对应记录。新数据随 schema 7 工作区备份保存，旧版工作区自动事务迁移。见[项目管理说明](docs/p1-management.md)。

## 记忆与恢复

- SQLite 是正式状态的唯一存储；原件单独保存，证据引用稳定的片段 ID。DOCX 保留段落/表格定位，PDF 保留页面定位。
- 候选保留人工/AI来源、模型、提示版本、提取任务和原文摘录；编辑不抹掉来源。修订正式记忆必须写原因，旧版本与依据完整保留。
- 原文解析与模型请求使用独立工作线程，不阻塞数据库线程。每批成功后，在短事务内保存检查点、校验问题和候选；后续失败不删除已有成果。待确认候选及组织待审核草稿均不进入正式记忆检索。
- 当前提取提示版本为 `project-memory-task-extraction-v9-conversation-retention`：优先逐字保留完整事实句，保持主体、代词、大小写、数值、数学/LaTeX写法、否定和条件，再从正文及引文的相同字面片段提取可选组织字段。初始批次最多2400字符，输出上限6144 token；数量、正文及引文长度同时受协议和运行时限制。任务守卫设置为512次请求、累计300万实际报告/保守预留token的止损阈值、20分钟活动耗时；失败父请求同样计入预算，未报告usage时保守预留并标记未知。
- 重启恢复未完成任务；取消任务不自动复活。旧版本工作区自动事务迁移，仍可恢复第一阶段备份。
- 还原先校验完整性与数据约束，再自动创建当前状态安全副本。旧工作任务的迟到结果不能写入还原后的工作区。
- **从备份还原的 AI 任务会暂停**，需要手动重试后才会调用模型。还原保留本机模型设置，不从备份导入凭据。
- 检查点、原始候选、审核原因和提取预算台账随备份保留；还原旧备份时保留本机已发送请求的预算高水位，恢复任务不能退回已消耗额度。配置或资料快照发生变化时，重试会新建提取任务，不把旧结果换成新来源。
- 第三阶段备份包含任务、原文依据、全部进展事件、任务候选和日报各版本；校验引用及领域约束后整体还原。兼容第一、二阶段备份，迁移不会虚构任务和日报。

## 密钥与本地数据

- macOS 默认目录：`~/Library/Application Support/com.projectassistant.desktop/workspace`，应用内可查看实际位置。
- 密钥和设备模型设置位于工作区 `secrets/ai-settings.json`，不写入 SQLite、任务记录、日志或备份；读取接口只返回是否已配置密钥。端点变更时清除旧密钥，防止误发到另一服务。
- 默认私有文件使用用户专属目录/文件权限。Windows / macOS 可在“桌面运行与数据保护”启用系统凭据保护：系统保存加密密钥，AI/飞书私有配置使用 AES-256-GCM 加密。迁移或系统凭据不可用会明确报错，不能自动降级为明文。
- 本机自动/手动备份为未加密 ZIP，包含一致数据库快照、原件和校验清单；导出可使用至少12字符密码生成 AES-256-GCM + scrypt 加密的 `.pabackup`。密码不保存。备份不包含其他备份、模型设置或密钥。
- 默认不自动调用模型。云端外发只发生在用户配置并授权之后；本机 Ollama 仅允许回环地址。
- `PROJECT_ASSISTANT_DATA_DIR` 可指定隔离工作区。开发和验收全部使用隔离目录，不写入正式资料。

## 直接体验测试版

Windows 用户安装 `target/release/bundle/nsis/` 中的安装包后，从开始菜单打开“项目助理”，只显示应用界面。需要本机快速体验时，运行 `npm run desktop:build -- --debug --no-bundle`，然后双击 `target/debug/project-assistant-desktop.exe`；该版本内置前端页面，无需另外启动命令行或开发服务器，也不会弹出黑色控制台窗口。

交付目录中的 `项目助理-macOS-arm64测试版.zip` 适用于 Apple Silicon Mac。解压后打开 `项目助理.app`。这是本地测试构建，尚未完成正式开发者签名与公证。

首次打开是空工作区。“先看看示例”会在你主动导入后建立样例资料。云端使用自己的模型账户，应用不附带 API Key。

## 开发启动

需要 Node.js 22 LTS 或更高版本 / npm、由 `rust-toolchain.toml` 锁定的 Rust、系统 Tauri 编译环境。macOS 使用 Xcode Command Line Tools。

```bash
npm install
npm run desktop:dev
```

构建：

```bash
npm run desktop:build
# Apple Silicon Mac 本机测试包
npm run tauri -- build --debug --bundles app
```

### 固定义务与增量回答（qa-structured）

当前实现先从原问固定回答义务，再逐条审查事实和未知项；同一回答中的正确事实不能为错误主体的事实提供信任。必要补查只生成缺少的断言，经明确一致性审查和两份当前快照校验后合并。每条最终断言保留实际生成及检索来源，协议失败与安全回退分别计数。
