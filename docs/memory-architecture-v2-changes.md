# 第二轮架构修复依据

第一轮使用 `qa-architecture-dev`，完整结果、151 次调用和 1,288,508 tokens 均保留。自动评分为桌面和连接器各 13/19，问答阶段消耗 753,084 tokens；这不满足提高正确率的目标。第二轮仍用同一份 929 条确认记忆、原文、20 题、模型和评分程序，不重新提取，不覆盖第一轮结果。

本轮修复三类通用问题：

- 生成审查原判“无需修订”，但后续本地对象检查删除错误层级断言时，原判已不适用。将实际删除的断言、原问题、保留断言和当前引用绑定作为一次修订依据，重新生成并审查；不直接放宽对象检查或强制判完整。
- 一条原文片段可包含多项事实。引用它不代表答案已陈述其中所有事实。允许对同片段中明确未陈述的字面事实提出修订观察，并区分支持正文和答案正文；观察本身不成为事实依据。
- 原文只按问题词面排序，会漏掉已选中原子事实的必要上下文。优先读取实际已选记忆通过当前修订证据关联的完整原段，再用词法匹配补充；仍受原有项目、来源、修订、日期和数量预算约束。

问题计划增加直接的回答重点：计数绑定所问角色及阶段，不发明更广总人数；组成回答所问单位；过程说明记录中的输入、操作及输出选择；综述说明代表方法的特征。所有提示只来自问题类别，不包含评测实体、题目 ID 或标准答案。

人工复核也发现评分口径限制：综述题的人工短答案列举四个系统，自动裁判进一步要求具体测试结果；部分架构题存在“本文方法/相关工作”的指代差异；权重题标准答案接受独立解码器的推断，而原文没有明确说明参数共享。这些不会转化为按题目定制的生产规则，原自动评分继续保留，不能为提高分数编造缺失关系。

第二轮仅在测试通过、源码及二进制重新冻结后运行。沿用登记的最后一次开发集尝试，最多 300 请求 / 160 万 tokens，所有开销继续累计。
