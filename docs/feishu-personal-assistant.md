# 飞书个人账号助理

个人账号模式支持两种触发：已绑定的飞书群里有人 @你，或已绑定同事发来私聊。助理查询新消息，按会话绑定检索指定项目已确认记忆的当前版本，调用配置的模型，再以完成授权的个人账号回复原消息。私聊无需 @你。

这是消息搜索轮询，存在轮询和飞书搜索索引延迟。桌面应用需要保持运行且电脑能够访问飞书及所配置的模型服务。首次启用从启用时间开始处理，不自动补发历史问题。普通群聊天、@全体成员、本人发出的消息、机器人消息、未绑定的群或同事不触发代答。支持文字与富文本，不自动读取图片、附件或语音。

## 首次配置

1. 在[飞书开放平台](https://open.feishu.cn/app)创建企业自建应用，取得 App ID 和 App Secret。根据企业要求完成应用上线和权限审批。
2. 配置 OAuth 重定向地址：`http://127.0.0.1:17179/feishu/callback`。授权期间需保持本机 17179 端口可用。
3. 为应用配置用户身份权限：`offline_access`、`search:message`、`im:message.p2p_msg:get_as_user`、`im:message.group_msg:get_as_user`、`im:message`、`im:message.send_as_user`、`im:chat:read`。自动采集文档还需 `docx:document:readonly`、`wiki:wiki:readonly`，增加权限后需重新授权。其中 `im:message.send_as_user` 使用点号。以实际应用后台的权限可用性和审批结果为准。
4. 在助理侧栏打开“飞书个人助理”，输入并保存应用凭据，点击个人账号授权，在浏览器的飞书页面完成授权。
5. 核对界面显示的授权账号。在“自动回复”页选择群或同事并绑定本地项目。每个会话绑定一个项目，该项目所有已确认的当前记忆都可能成为回答依据，请选择适合向该群或同事分享的项目。
6. 在“模型设置”配置模型并保存。远程模型需要允许发送资料；问答复用此授权，发送本次问题、检索出的记忆和原文定位。
7. 可先使用问答预览核对答案，然后启用自动回复。默认关闭，轮询间隔至少 30 秒。

飞书应用承担 OAuth 和 API 权限；回复使用 `user_access_token`，不会降级成机器人身份。仅有个人登录并不等于已获得应用权限，企业管理员仍控制应用上线和能力审批。

## 开启同事私聊自动回复

1. 在飞书开放平台为应用增加用户身份权限 `im:message.p2p_msg:get_as_user`，完成权限审批与应用发布，再在“连接账号”点击“重新授权”。已有群聊授权不会自动获得新增权限。
2. 在“自动回复”点击“读取最近私聊”，再点击“添加同事私聊”。列表来自最近 30 天、最多 500 条消息涉及的会话；仅用于选择同事，不补发历史消息，也不保存这些消息正文到项目资料。
3. 选择同事和允许回答的项目。列表没有该同事时，可手动填写私聊会话 ID（`oc_…`）及同一应用下该同事的 Open ID（`ou_…`）。后台会核对飞书返回的会话类型和对方身份；群 ID 无法冒充私聊。
4. 勾选“回复此同事私聊”和“用我的账号自动回复”，保存。只处理启用后的新消息；新建、重启用、更换同事或项目的绑定从修改时开始，不追溯补发。
5. 同事发来的新文字或富文本消息无需 @你。只有绑定项目记忆足以回答时才发送；没有依据时在左侧一级导航“聊天回复”显示跳过。该记录保留私聊类型、同事和项目，移除绑定后仍可查看。

私聊与群聊共用个人账号授权、模型配置、发送前依据校验和消息去重。修改设置、断开授权、还原工作区会取消旧处理；发送结果不确定时不会自动重发。自动回复与“记忆中心”的资料采集分别配置，开启私聊代答不会自动将私聊收进项目记忆。

## 项目记忆采集

群与文档的自动采集在“记忆中心”单独设置，不要求 @你，也不要求开启自动回复。原文保存后空闲提取、比较，冲突由用户确认。详见[记忆系统说明](memory-system.md)。

## 运行和恢复

- 左侧一级导航“聊天回复”直接展示同事提问、助理回复、项目、会话类型、处理状态和错误。支持项目、私聊/群聊、状态与文字筛选，筛选范围为最近 50 条处理记录，页面每 5 秒刷新。未确认发送成功的生成内容会单独标明，不能当作已发送回复。
- “立即检查”触发一次后台查询，不会打开历史补发模式。账号连接、会话绑定和回答预览仍在“飞书设置”弹窗，弹窗不再保留回复记录页签。
- 修改绑定或暂停会使当前处理失效。模型设置改变后，旧模型生成中的回答取消；之后的处理使用新设置。
- 记忆修订或工作区还原后，旧快照生成的回答无法通过发送前校验。还原会暂停飞书自动回复，需要核对项目绑定并重新启用。
- 消息处理记录单独保存在本机 `feishu-runtime.sqlite`，不随项目备份倒退，因此还原旧项目备份不会重新回复处理过的消息。
- 凭据和令牌位于本机 `secrets/`，不通过状态接口返回、不写入项目备份。Unix 使用私有文件权限，Windows 将秘密目录限定为当前用户与 SYSTEM 访问；文件内容不声称经过加密。
- 发送结果不确定时记录为待核对，不自动盲目重发。凭据过期、缺少权限、接口限流或模型出错会保留错误信息。
- 断开授权会清除本机个人凭据并停止自动回复。需要完全撤销飞书侧的授权时，可同时在飞书账号的授权应用中取消授权。

## 记忆问答边界

检索只使用指定项目内 `active` 记忆的当前修订，排除待确认候选和历史版本。回答附当前记忆版本及其原文定位；无原文的人工纠正会明确标注。没有相关记忆或模型判断依据不足时不自动回复，状态中说明原因。

当前采用中文字符二元组与英文词匹配召回，再由模型判断依据。它可能漏掉不同说法的同义问题。引用校验保证引用来自本次召回集合，不代表模型对原文含义的判断必然正确。任务进展不会自动进入本模块的记忆答案，需要在项目记忆中确认相应事实。

## 开发与验证

核心模块：`crates/core/src/feishu.rs`（授权、查询、发信与运行记录）、`qa.rs`（检索和带依据回答），界面为 `src/components/FeishuSettings.tsx`。后台网络不在数据库 actor 上执行，也不会启动第二个 Engine 争用工作区锁。

```sh
cargo test -p project-assistant-core --locked
cargo clippy -p project-assistant-core --all-targets --locked -- -D warnings
npm run build
```

自动化测试使用隔离临时目录和本机 HTTP 夹具，不使用真实个人账号、项目资料或飞书凭据，不向真实成员发送消息。真实联调需在应用内完成个人授权后，使用另一账号分别在已绑定测试群 @本人、向本人发送不带 @ 的私聊，并核对发送者身份、项目范围、引用内容和重启去重记录。当前自动化测试覆盖私聊筛选、会话身份核对、群聊规则保留、历史起点、重启去重、证据不足与发送不确定等路径；不代表真实账号联调已完成。
