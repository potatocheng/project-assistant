# 飞书个人账号助理

个人账号模式的处理流程：项目成员在已绑定的飞书群里 @你 → 助理查询新消息 → 按群绑定检索该项目的当前任务、进展、风险、里程碑、管理记录及已确认记忆 → 使用与桌面项目问答相同的回答流程 → 以完成授权的个人账号回复原消息及依据。

这是消息搜索轮询，存在轮询和飞书搜索索引延迟。桌面应用需要保持运行且电脑能够访问飞书及所配置的模型服务。首次启用从启用时间开始处理，不自动补发历史问题。普通群聊天、@全体成员、本人发出的消息、未绑定的群不触发代答。

## 首次配置

1. 在[飞书开放平台](https://open.feishu.cn/app)创建企业自建应用，取得 App ID 和 App Secret。
2. 配置 OAuth 重定向地址：`http://127.0.0.1:17179/feishu/callback`。授权期间需保持本机 17179 端口可用。
3. 在助理侧栏打开“飞书个人助理”，输入应用凭据，点击“自动申请权限并连接”。项目会先保存设置，再打开飞书官方的应用更新确认页，自动填好所需权限；用户只需确认或取消，无需到后台查找和勾选权限。企业要求审批时，仍需有权限的管理员确认。
4. 应用权限确认完成后，项目自动打开个人账号授权页。确认个人授权后，账号状态会自动更新。应用权限已经开通时，可展开“将申请哪些权限”，使用“仅重新确认个人授权”恢复账号连接。
5. 核对界面显示的授权账号。在群绑定页选择或填写群 ID，绑定本地项目。该项目的任务、跟进、风险、决策、里程碑、报告和当前确认记忆均可能成为群回答依据，请选择适合在该群分享的项目。
6. 在“模型设置”配置模型并保存。远程模型需要允许发送资料；问答复用此授权，发送本次问题及筛选后的项目记录。自动回复仍要求有效模型配置与资料授权；明确的任务字段、跟进排序、待决策清单和交付延期信号清单可由本地规则直接回答，不消耗模型请求。
7. 可先使用问答预览核对答案，然后启用自动回复。默认关闭，轮询间隔至少 30 秒。

飞书应用承担 OAuth 和 API 权限；回复使用 `user_access_token`，不会降级成机器人身份。仅有个人登录并不等于已获得应用权限，企业管理员仍控制应用上线和能力审批。

## 权限自动申请

项目使用[飞书官方 SDK 的应用注册/更新协议](https://github.com/larksuite/node-sdk/tree/main/scene/registration)：通过设备授权申请更新已有应用，确认链接携带当前 App ID 和 gzip + Base64URL 编码的 `addons`。设置 `preset: false` 并仅声明项目所需的用户身份权限，避免附带默认模板的业务权限。此流程无需额外开通应用管理权限，也不获取租户令牌。

应用申请和个人 OAuth 使用同一份权限定义：`offline_access`、`search:message`、`im:message.group_msg:get_as_user`、`im:message`、`im:message.send_as_user`、`im:chat:read`、`docx:document:readonly`、`wiki:wiki:readonly`，覆盖自动回复和记忆采集。增加功能权限后再次点击连接即可申请更新。

后台按飞书返回的间隔检查确认结果，遇到限流放慢轮询；拒绝或过期会显示可重试的提示。重复点击复用未结束的请求。关闭设置窗口后后台仍可继续，重新打开窗口会恢复授权页面。断开账号、修改设置或还原工作区会取消本次请求，迟到的确认结果不能覆盖新设置。飞书返回的应用 ID 必须与当前应用一致，凭据只保存在本机秘密目录，不会通过状态接口暴露。应用权限确认不会代替个人 OAuth 的同意操作。

## 项目记忆采集

群与文档的自动采集在“记忆中心”单独设置，不要求 @你，也不要求开启自动回复。原文保存后空闲提取、比较，冲突由用户确认。详见[记忆系统说明](memory-system.md)。

## 运行和恢复

- “立即检查”触发一次后台查询，不会打开历史补发模式。最近记录显示问题、项目、处理状态、回复和错误。
- 修改绑定或暂停会使当前处理失效。模型设置改变后，旧模型生成中的回答取消；之后的处理使用新设置。
- 任务、项目管理记录、记忆修订或工作区还原后，旧快照生成的回答无法通过发送前校验。还原会暂停飞书自动回复，需要核对项目绑定并重新启用。
- 消息处理记录单独保存在本机 `feishu-runtime.sqlite`，不随项目备份倒退，因此还原旧项目备份不会重新回复处理过的消息。
- 凭据和令牌位于本机 `secrets/`，不通过状态接口返回、不写入项目备份。Unix 使用私有文件权限，Windows 将秘密目录限定为当前用户与 SYSTEM 访问；文件内容不声称经过加密。
- 发送结果不确定时记录为待核对，不自动盲目重发。凭据过期、缺少权限、接口限流或模型出错会保留错误信息。
- 断开授权会清除本机个人凭据并停止自动回复。需要完全撤销飞书侧的授权时，可同时在飞书账号的授权应用中取消授权。

## 统一项目问答边界

桌面、飞书回答预览和群代答复用 `assistant_qa` 的检索、字段查询、模型生成与依据校验。范围包括当前任务和最近进展、有效依赖与阻塞、确认排期、跟进记录、项目目标与里程碑、风险与决策、需求变更、交付验收、会议、报告及已确认记忆。报告按生成时快照使用，不覆盖任务的最新状态；潜在风险或依赖不能证明实际上线已经延期。

群入口 `ask_project_question` 必须指定一个项目，拒绝空范围和 `all`。群消息不能改变绑定项目或调用任务修改工具。记忆仍只使用 `active` 当前修订，排除待确认候选与历史版本。回复附记录类型、名称、可用版本及更新时间；记忆保留原文定位。部分可答时保留已知信息并说明缺项；仅询问的负责人或截止日期均未记录时标为未知，不自动发送。引用存在不代表语义必然正确，关键判断仍应核对记录。

检索有数量与长度上限，模型最多5次请求并共用超时与用量预算。预览展示回答范围与记录依据；同一问法可能漏召回同义表达，宜写清事项名称。旧 `ask_project` 保留为只读记忆问答兼容接口，历史记忆评估继续使用它，不再作为飞书代答入口。

## 开发与验证

核心模块：`crates/core/src/feishu.rs`（个人授权、查询、发信与运行记录）、`crates/core/src/feishu/permissions.rs`（自动申请应用权限与确认轮询）、`assistant_qa.rs`（统一检索和回答）、`question_flow.rs`（调用预算和核验），界面为 `src/components/FeishuSettings.tsx`。后台网络不在数据库 actor 上执行，也不会启动第二个 Engine 争用工作区锁。

```sh
cargo test -p project-assistant-core --locked
cargo clippy -p project-assistant-core --all-targets --locked -- -D warnings
npm run build
npm run evaluate:project-questions
# 可选真实模型验证：使用环境变量 DEEPSEEK_API_KEY，仅发送隔离合成项目
npm run evaluate:project-questions:live
```

自动化测试使用隔离临时目录和本机 HTTP 夹具，不使用真实个人账号、项目资料或飞书凭据，不向真实成员发送消息。真实联调需在应用内完成个人授权后，在一个已绑定测试群中用另一账号 @本人，并核对发送者身份、引用内容和去重记录。

统一接口、回答行为及合成场景的真实模型实测见[项目经理统一问答与验证](project-questions.md)。
