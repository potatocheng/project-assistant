# 上下文提取、分区补提与逐条审核（v8）

本文保留 v8 基础机制与当时实测。当前 v9 在此基础上新增聊天关系与保留策略，见[聊天记忆分层与上下文](chat-memory-retention.md)。

提取提示版本为 `project-memory-task-extraction-v8-partitioned-candidate-review`。复用原文 segments、候选、修订和提取检查点；原文和证据 ID 不变。v7 的历史评测仍保留在 [v6/v7 对照报告](memory-context-live-report.md)，本轮修复单独记录在 [v7/v8 定向复测](memory-context-fix-report.md)。

## 阅读计划

`extraction_context.rs` 在原有句界窗口上增加双向完整邻段、Markdown 标题层级、列表引导语、Markdown 表头以及 DOCX 表头和同行段落。上下文保留原始 segment ID 与原文字面片段，不合成表格事实或推定标题就是每个事实的主体。

初次阅读正文最多 2400 字符，局部复查最多 4800 字符，包含附加上下文。普通窗口有空间时补全被切开的片段。正文提取区域 `primary` 和阅读上下文分开传入模型，本地检查候选至少有一处引文位于 primary。纯上下文候选不能反复提升为提取成果。

## 饱和分区补提

按模型原始数组长度检测饱和：记忆达到 12 条或任务达到 4 条，先分区，再考虑普通局部复查。检测发生在证据校验、primary 过滤和去重之前，避免过滤后掩盖容量信号。

饱和父批次记录为 `partitioned`。按完整句子的数量均分成两个不重叠 primary，沿用原文 ID，不受原来容量错误拆分的 800 字符下限约束，因此短而密集的 18 句也可以补提。子分区不会重新展开成整段饱和正文；可在原文中补前后各一句阅读上下文，以及其他结构上下文。分区最多到第 4 层，并共享原有批次数、请求数、token 和耗时上限。单个不可再分的句子或达到深度上限时保留覆盖警告，不做同大小的饱和重试。

父批次已经验证的记忆、任务保留，子分区补充结果按现有内容、范围及证据规则去重；子分区合法返回空结果或失败不会抹掉父批次成果。父批次候选仍逐条过范围与上下文门禁，不因分区而获豁免。不同措辞或不同范围的候选仍可能并存。

## 每条候选独立检查

`context-plan-v2-per-candidate` 保存与候选索引一一对应的 `candidateIssues`，批次 `issues` 只汇总展示和触发复查。持久化时只将当前条目的问题用于状态判断，索引缺失则拒绝该检查点事务；旧版检查点兼容原有整体审核语义。

检查以不可变的完整原文为依据，不限于当前重叠窗口。逐条核对：有条件／否定的原句是否被候选截短；“上述计划”等后置限定是否跟着前文事实保留；单独限定语是否缺少所指事实；列表条目是否保留引导语中的范围；必要结构上下文是否完整提供。完整候选不能豁免同批次、同资料其他窗口的短句。没有指代关联的相邻项目不会自动互相继承条件。

普通非饱和批次存在疑点且有可保留记忆时，保存 `review_pending` 后执行一次局部复查。复查返回替换候选，再逐条检查；只要本条仍有上下文或范围问题，就进入 `needs_review` 且不创建可确认提案。完整条目进入 `ready` 待原有确认流程。合法空复查保留仍有有效证据的初次候选并重新检查。复查前的候选与疑点留档供核对。

批次处理完成、没有检测到问题、进入 `ready` 都不是语义完整证明，也不等于已经确认入库。已确认或人工编辑的事实不被此次升级自动改写，任务候选继续走原有确认流程。

## 恢复与成本

正文、primary、复查输入、是否分区及提示版本参与检查点身份；`partitioned`、`review_pending`、成功子分区可复用。中断重试只请求尚未完成的分支。检查点保留累计预算，复用请求前预留、每日额度、每任务 512 次请求／300 万 token／20 分钟活动耗时和资料版本守卫。容量错误仍按原有有界拆分规则处理。

资料页区分“已安排局部复查”“饱和批次已安排分区补提”和仍待核对的疑点。父级警告是历史诊断，不能据此把子分区的全部候选判成不完整。

## 验证和边界

回归覆盖：短密集正文的无重叠分区、Unicode 字符完整性、分区深度、原始记忆／任务饱和、不可分句的终止、父级成果保留、失败子分区恢复、完整／不完整同伴的分别审核、跨窗口审核、列表范围、无关邻段、持久化去重与备份校验。

当前审核是保守的字面与结构规则，可能多拦，也会漏掉未覆盖的语义改写、复杂远距离指代、PDF 多栏关系；不是通用语义证明。分区按句子数量近似事实密度，单句包含超过输出上限的事实仍可能遗漏。已有 v7 候选不会自动重新审核，需要重新提取或人工处理。真实模型定向复测只说明登记诊断样本上的表现，不能代替盲测或业务资料人工标注。
