# 项目经理统一问答与验证

桌面“项目问答”、飞书“回答预览”和个人账号群代答共用当前项目记录的检索与回答流程。项目经理可以问最新进展、阻塞、延期信号、跟进对象、待决策事项和已记录的决策原因；回答保留对应记录及版本依据。

## 使用与接口

- 桌面选择单个项目或全部项目，可保留会话并指定事项追问。
- 飞书设置中将群绑定到一个项目，先在“回答预览”试问。预览只在本机显示；启用群代答后，新 @本人消息才触发回复。
- 群问答包含任务、最近进展、有效依赖、确认排期、跟进记录、目标、里程碑、风险与决策、变更、验收、会议、报告和已确认记忆。绑定项目的这些记录可能被群成员看到，请按实际共享范围选择项目。
- 群代答发送前复核绑定、账号、模型设置、工作区以及项目记录快照。任务更新、记忆修订等会取消已经过期的答案。

`ask_assistant` 继续支持桌面项目范围与本地模式。`ask_conversation` 在其上保存会话。新的 `ask_project_question` 是群代答和飞书预览的共同入口：

```json
{
  "projectId": "一个本地项目 ID",
  "question": "哪些交付可能延期？",
  "date": "2026-10-28",
  "useModel": true
}
```

`projectId` 必须是一个存在的项目，不能省略或使用 `all`。`date` 可省略，默认使用本机当天；它用于评估当前记录，不是历史状态还原。`useModel` 默认开启，须有可用模型配置及必要的资料发送授权；显式设为 `false` 可离线验证。桌面原有模型不可用时的本地回退行为保留。

旧 `ask_project` 继续提供记忆问答兼容接口，既有记忆基线评估仍使用它。

## 回答行为

直接查询明确任务的负责人、截止日期时读取当前字段。两个字段只有一个已记录则返回 `partial`；询问字段全部未记录则返回 `unknown`，不会借用其他任务、里程碑或审批人的信息。追问拍板人、预算等额外信息不会被两个字段的快速查询吞掉。

“今天先跟进谁”按已有的阻塞、逾期、到期和长期未更新规则排序，并尊重暂缓跟进设置。“有哪些待决策事项”筛选未关闭决策。“哪些交付可能延期”整理已有日期后移、逾期、阻塞及需复核信号，明确属于当前记录提示。这些明确查询无需模型请求。

带原因、沟通方案、排期调整或其他额外要求的问题继续使用已配置模型及证据核验，不用固定清单代替完整问题。模型生成与核验均强调：没有某事的记录不等于该事明确未发生。

群回复附记录类别、名称、可用版本、更新时间和原文定位。部分回答保留已知信息；全部无依据时跳过自动发送。模型输出仍可能出现语义错误，引用存在不是准确率保证，关键决策需要核对记录。

## 2026-10-28 验证

固定题集位于 `crates/core/tests/fixtures/project-manager-questions-v1.json`。它是贴近日常交付的合成项目，包含已完成任务重新打开、证书阻塞、验收日期后移、关闭与未关闭决策、缺失负责人或日期，以及不在项目内的服务器问题。

12 类问题分别通过桌面和群预览入口执行，共 24 个用例。离线检查 24/24 通过；最终配置真实 DeepSeek 模型的运行检查 24/24 通过，其中 16 个用例由本地字段或业务规则回答，其余 8 个用例实际生成并核验，合计 16 次真实模型请求、37,118 个提供方报告 token。用量报告完整。

已逐条由 Codex agent 对照固定资料核对最终回答，确认当前进度、负责人、日期、风险信号、待拍板状态、决策原因和未知信息与本题集一致。这不是人工金标，也不是业务准确率估计。自动关键词检查曾漏过“没有延期记录”被改写为“明确未延期”的语义问题，因此同时保留规则回归、反例检查和逐条语义阅读。

完整核心回归 517 项通过、6 项按既有条件忽略；最终调整后另外复跑了相关问答流程单元测试、桌面/群问答集成测试、管理记录联动及查询范围边界。核心 Clippy（警告视为错误）、格式、前端生产构建与桌面 `cargo check` 均通过。

机器可读结果见 [验证快照](project-question-validation.json)，包含全部最终回答、引用类别、状态、检查结果和题集/二进制哈希。调试与最终实测合计 88 次真实模型请求、202,236 个提供方报告 token；四轮原始请求、原始响应和 usage 保留在快照标识的本机 `.local-data/project-questions-*/results.json` 中。

所有验证使用隔离工作区，不读取正式项目资料或真实飞书凭据，不向真实成员发送消息。真实业务项目的质量及真实群联调仍需使用对应项目数据和已授权测试群验收。

## 复跑

```sh
cargo build -p project-assistant-core --bin pm-host --locked
npm run evaluate:project-questions
# 环境变量 DEEPSEEK_API_KEY 必须已设置；实际调用模型并产生用量
npm run evaluate:project-questions:live
```

真实模型评估单次最多 40 个上游请求，真实密钥仅在评估进程内使用，隔离工作区只保存一次性本机代理令牌。`PROJECT_QUESTION_MODEL` 可覆盖默认 `deepseek-flash`；`PM_HOST_BINARY` 可指定独立构建目录的可执行文件，以免影响正在运行的应用。
