# 第三阶段验收：每日清单、进度与日报

日期：2026-10-19（Asia/Shanghai）。版本：0.3.0。数据库：schema 3。

## 实现范围

- 任务池与每日清单支持项目、日期、状态筛选，区分个人执行和跟进交付；未排期事项可加入指定日期，未结与逾期事项持续可见。
- 每次任务修改保存业务日期、实际记录时间、修改前后快照、说明及版本。重复请求幂等，同一请求 ID 改写内容会拒绝；旧版本更新和逆序业务日期被拒绝。
- 从记忆建立任务时固定当前修订版本与该版本依据。人工进展不继承原文证据。AI 任务候选独立保存，明确确认后才创建任务或应用到同项目的已有任务。
- 日报在本地根据当天事件生成，不依赖模型。使用该日期已知的任务快照，区分完成、推进与跟进、阻塞与逾期、后续安排；同日完成后重开不计入完成。
- 保存日报修改会创建新版本，保留生成时的依据；支持查看旧版、原生复制和 Markdown 导出。后续改名或状态改变不污染历史清单和日报。
- 完整备份覆盖任务、事件、依据、任务候选、全部日报版本和幂等回执。恢复前进行引用和领域校验；兼容真实 schema 1/2 备份，恢复后的 AI 仍需人工重新触发。

- 日报包含两条当天事件及两项任务快照，状态显示中文。点击复制后粘回正文，内容不变且仍显示已保存。

## 浏览器界面验收

开发浏览器通过仅本机桥调用同一 Rust 核心，使用独立合成资料工作区。已实际完成任务创建、进行中 60% 到完成 100%、跟进事项逾期、前一天清单不泄露后来创建的任务、日报编辑另存与只读旧版、复制和下载。

Markdown 下载与 Rust 保存版本逐字一致；人工补充只出现在新版本，原有依据保持一致。900×680 下检查清单和日报页面，无横向溢出。

最终干净验收页控制台 0 errors / 0 warnings。此前测试页保留一次未填写测试密钥时的预期配置校验 HTTP 400，与运行异常分开记录；没有删除历史日志来隐藏错误。

AI 界面验证使用明确标注的确定性 HTTP 测试服务：自动产生任务候选、核对原文、新建正式任务、第二份进展资料生成候选、由用户选择已有任务并比较后确认更新为 60%。任务其他信息保持不变，进展历史与逐字引用均可追溯。关联目标默认为空，用户未明确选择并读取当前版本时不能确认。

## 交付边界

真实 DeepSeek 认证与提取质量仍按用户选择留待稍后配置。当前 AI 协议与候选流程验收不代表真实模型质量；逐字引用存在也仍需核对语义。

日报当前是可核对、可编辑的本地模板，没有模型润色、办公平台同步或自动发送。macOS 为本地测试构建，尚未完成正式开发者签名与公证。

GitHub 公开仓库 [potatocheng/project-assistant](https://github.com/potatocheng/project-assistant) 管理源码与设计文档，不管理应用中的项目资料；已配置忽略规则与只读 CI。实际远端检查结果见 GitHub Actions。
