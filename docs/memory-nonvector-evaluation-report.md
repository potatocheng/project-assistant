# 无向量记忆优化实现与评估

报告生成时间：2026-10-20T08:19:24.863Z。

## 已实现能力

- 两个入口共用当前记忆筛选、全量合格正文的BM25排序、字段相关性与节选；保留项目、修订及冲突限制。
- 常用术语归一化，明确唯一任务的负责人/截止日期直接读取，减少宽泛意图词造成的错误路由。
- 初次依据不足时，用当前可见记忆的短目录帮助改写检索词，再补查一次。目录最多48项、约8000字符；重复编号笔记合并为导航项。目录与改写都不作为答案证据。
- 因果、延期前提及负责人/截止字段问题按需通过独立模型请求核验，核验拒绝或失败则取消生成结论。
- 每题最多4次模型请求，累计输入及schema120000字符，每次结果16000字符；模型阶段共享设置超时，无自动网络重试。字符限额不是精确token限额。
- 问答只读，新增检索轨迹和核验状态；补查及回答前后核对配置、工作区和数据版本。

当前没有embedding、语义重排模型或向量数据库。后续向量索引基于组织后的正式记录与证据构建。

### 逐题语义复核

以下由编码助理复核，非独立人工盲评：

- 最终36题没有协议错误；桌面关键事实与标准引用命中15/15，飞书14/15；两端无答案题均3/3拒答。这些是规则命中指标，不能标为完整回答准确率。
- 商务确认问题经目录辅助改写后找到客户签字记录。最终回答说明未记录名为商务确认的事项，并分别陈述账单、签字和验收事实；未再明确断言供应商账单缺失导致客户签字暂缓。原题把商务确认映射到客户签字也存在事项歧义，需真实业务标注确认。
- 多原因问题最终均说明未证实实际上线延后，并保留已知依赖与供应商对接人。联系供应商对接人可作为核对建议，仍不能视为已经确认其负责补账单。
- 故障问题以10月18日故障定位答案，桌面还说明无法确认其是否就是用户所指的上次中断。核验规则修正后不再要求用户问题中每个未知前提本身为真。
- 新增采购负责人未知题最终均未将通用采购审批人代填为泽川安全密钥采购负责人；飞书初始生成仍混淆事项，后续字段核验拒绝了该回答，说明独立核验有实际作用。
- 新增归档题保留七年后仍需法务批准的条件；开发完成与验收未启动分别陈述，92%保留为测试覆盖率。权益领取题找回实名核验与身份证限领规则。
- 飞书对天衡发布为何已经推迟继续拒答，没有利用已知压测阻塞给出部分回答；这是仍有改进空间的保守拒答。桌面明确未证实推迟并给出已有记录。
- 仍有无关背景混入和引用不够精简：桌面重复领取题附述其他故障、对账与上线记录，却只引用领取规则；此类附加事实没有逐项引用，也未全部触发按需核验。关键事实命中和引用ID合法无法覆盖这一缺陷。
- 飞书二次验证题在泽川硬件安全密钥规则后并列通用短信否决、保留邮箱验证码的记录，未明确两者是否同一事项，存在范围表述风险；桌面明确了该对应关系未知。后续应完善实体与事实适用范围，再评估向量召回。
- 模型核验是同一模型的独立请求，仍可能误判。下一阶段应独立标注全部原子断言、引用完整性与无关内容，增加真实业务和未见样本；不将这组小型合成测试外推到生产质量。
