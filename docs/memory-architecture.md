# 记忆问答架构：确认事实、原文语境与一次修订

本轮让问答同时使用当前确认记忆和明确标注的原文段落。确认记忆继续承担已接受事实、人工修订和适用范围的管理；原文补充被原子化提取省略的关系、条件和上下文，不自动写入或升格为正式记忆。这里记录实现与边界；[最终实测摘要](memory-architecture-final-summary.md)显示提升主要集中在桌面入口。[第一轮实测](memory-architecture-dev-report.md)及其成本保留，[第二轮修复依据](memory-architecture-v2-changes.md)单独记录。

## 从问题到实际证据包

`memory_query` 先按项目、当前修订、状态、待审冲突和日期筛选正式记忆，再做本地词法检索。`evidence_pack` 为焦点问答选择最多 24 条记忆；在字符预算允许时，优先保留排名靠前且直接命中问题的候选，保底名额为参考上限的一半。剩余名额用于互补事实和有依据的段落关系，避免密集的邻接关系奖励挤掉高排名直接事实。名额保底不豁免有效性和字符限制。

`source_passages::retrieve` 从实际选中的当前合格记忆的修订证据找到来源。先按选中记忆顺序轮转读取真实关联原段，每个锚点先取一个未重复段落，优先阅读最多 6 段、18,000 字符；再按问题词法匹配补足总共 8 段、24,000 字符。有余量时才继续读取其他关联段。这样原子事实的代词、条件及同段关系不会仅因词面匹配较弱而丢失。

补充检索可以选中同一来源中未被该条记忆直接引用的段落，但不会无锚点扫描任意资料、读取待确认候选作为事实或调用模型补提取。关系必须来自数据库中的当前 `revision_evidence`，不信任外部传入的导航链接。两个问答入口共用这条来源检索路径。

| 层级 | 当前限制 |
| --- | --- |
| 正式记忆候选池 | 最多 64 条当前合格记忆 |
| 焦点问答正式记忆 | 最多 24 条 |
| 来源检索 | 最多 8 个有合格锚点的来源；扫描上限 10,000 段、32 MiB 原文 |
| 来源段落候选 | 最多 8 段；每段最多 6,000 个 Unicode 字符，合计最多 24,000 字符 |
| 焦点问答实际包 | 最多 32 条参考、36,000 字符的模型上下文限制 |
| 断言支持片段 | 每个索引片段最多 600 字符，由当前参考正文确定 |

来源段落保持完整；超过单段上限的段落跳过，不截掉末尾条件再当作完整证据。原文候选也不保证全部进入模型：追加时还检查实际索引参考序列化长度，并预留问题及其他上下文空间。确认记忆先占位，来源段落利用余量；实际数量与内容以本次模型证据包为准。

32 条、36,000 字符是焦点问答路径的限制，不表示两个入口的所有业务模式统一为同一容量。桌面助理仍可加入任务、里程碑等已有结构化记录，概览模式保留既有 40 条、40,000 字符上限；正式记忆仍最多 24 条。具体请求的 `contextPack` 和问答轨迹记录实际使用范围。

## 原文身份和更新优先级

来源段落使用 `kind: source_passage` 和独立 `id`，不伪造 `memoryId` 或记忆修订号。可信上下文保存以下身份：

- `projectId`、`sourceId`、`segmentId`、`sourceVersionId`；
- 来源文件 `sourceHash`、完整段落 `contentHash`、原文正文与位置；
- `asOfDate`、合格 `anchorMemoryIds`；
- 远端来源的 `sourceOrigin`，包含提供方、远端标识、远端版本和抓取时间。

校验重新核对数据库中的来源状态、段落身份、正文、哈希、标题和位置，并核对锚点仍有效。入口还将项目和日期绑定到请求，重新检索并比较完整上下文，防止在模型调用期间资料变化后继续提交旧回答。模型只得到受限投影和正文索引；引用标题、版本和定位由程序从可信检索元数据渲染。

同一来源只要受以下任一情况影响，就整体不提供原文段落：

- 关联记忆已归档、已修订或当前修订正文不一致；包括人工纠正及内容未变的后续修订。
- 来自该来源的候选在人工编辑后被确认。这个路径仍可能是 `revision=1`、`origin=confirmation`，不能只按记忆修订号识别。
- 关联记忆存在待确认的冲突或不确定更新，或该来源自身存在待审冲突、不确定候选。
- 关联当前记忆的显式有效期不适用于本次日期。

检查使用历史 `revision_evidence` 追踪来源。人工纠正未附新证据时，其他未变的兄弟记忆也不能重新打开原先来源。此规则比逐句失效更保守，可能同时屏蔽来源内仍正确的其他段落；在建立可靠的句级替代关系之前，不以来源检索绕过人工治理。来源段落中仍可能含有相互矛盾的叙述，模型必须保留主体、时间、条件，并优先遵守当前确认记忆和人工纠正。

## 远端版本与普通导入的边界

`source_origins` 以项目、提供方和远端标识识别同一远端资料，按抓取时间及稳定的入库次序确定最新本地快照。存在更新快照时，旧来源即使仍为 `ready` 也不再进入原文证据；新快照正在解析或解析失败时，也不会回退旧来源。

这表示最新**本地已导入**快照，不表示已联网验证远端当前版本。普通手动导入没有远端标识或逻辑文档版本关联，同名标题、同名文件不能证明前后替代，也不能借此合并不同资料。远端编辑、删除或撤回尚未同步时，系统无法仅凭本地数据知道它们已经发生。

## 引用与事实依据

回答引用明确区分“确认记忆”和“导入原文（非正式记忆）”。来源引用保留真实来源及段落定位，前端可以打开原文；不显示虚构的“记忆 vnull”，不把原文支持伪装成已确认事实。

生成器用同一个实际包中的 `referenceIndex`、`spanIndex` 指定支持正文。程序将编号还原为精确文本，再检查引用集合、断言与支持片段的绑定。原文、问题、标题、旧答案和修订建议都是不可信输入；其中的指令不具有执行权。逐字引用只能证明文字存在，不能独立证明事实真实、对象正确或问题已被回答，仍需要语义审查。

## 审查完整包，再决定是否修订

语义审查收到本次生成实际使用的完整证据包，包括未被答案引用的可用段落。断言核验、遗漏检查和修订建议共用该包的引用编号空间；内部选择了参考子集时，审查也使用对应子集及其编号，不将候选池或另一轮包中的编号移入本轮。

每条断言仍只按自己的支持片段判断。包内其他文字可以说明答案存在遗漏，并触发重新生成，不能替已有错误引用补票。审查区分支持不足、回答了错误对象、必要信息遗漏、扩大问题范围及无依据地固定歧义解释；问题义务来自原始问题，不能因资料存在更多细节而增加用户没有询问的要求。

即使生成器返回零条断言或拒答，只要实际证据包非空，也执行审查，以发现“资料中已有答案却拒答”的情况。空证据包和无需模型的结构化字段路径不为此额外调用模型。

有效审查指出当前包内可修正的具体问题时，最多进行一次 `answerRepair`。审查原判无需修订，但本地对象检查随后实际删除了错误目标断言时，也可用原问题、被删断言、保留断言及其当前精确引用生成一次修订观察。只提出重新核验的要求，不直接放宽 guard 或判定已回答。

一个已引用片段可能包含多项事实。遗漏判断以答案断言实际陈述的内容为准；若同片段内仍有未陈述事实，`missingFactQuote` 必须逐字出现在当前支持片段中，且没有逐字出现在保留断言正文。这个检查只确认观察有文字依据，不能替代后续语义核验。

修订流程如下：

1. 本地检查建议对应原问题的字面片段、当前引用索引和具体断言。建议最多 3 项，合计最多 6 个支持片段，内容不超过 6,000 字符。
2. 在原问题和同一证据范围内生成一份完整替换答案，重新绑定每条断言；不机械拼接旧结论，不把审查建议当作事实。
3. 对替换答案再次执行完整审查和快照校验。
4. 生成失败、协议无效、审查不可用或没有保留下有据答案时，保留此前已经审查的安全结果；不得返回未经审查的新答案。此前本来就是拒答时，回退仍然是拒答。

一次原文修订与已有的“必要缺口本地补检、再生成”路径互斥，不层层叠加循环。修订结果被接受表示通过本轮约束，不等于自动证明它优于原答案。

## 请求预算与评测口径

单次问答最多 5 次模型请求、最多 2 次答案生成。修订占用唯一额外生成轮次，并且其再次审查也计入同一预算。问题改写、答案生成和审查的失败调用同样占请求额度，不自动重放认证、限流、网络或协议错误。

现有问答预算还限制累计输入 180,000 字符、每次输出 16,000 字符、配置的总耗时，并以提供方报告的 60,000 token 为调用后止损阈值。缺失 usage 明确记录为不完整，不能把未报告值解释为实际零成本；这个 token 阈值不是精确的请求前硬费用预估。

评测分别报告以下结果，避免把新增原文路径误记成提取收益：

| 指标 | 要回答的问题 |
| --- | --- |
| 正式记忆信息留存 | 提取并确认的记忆本身是否保留答题事实？分别列 `yes`、`partial`、`no`、`uncertain`，以及 `yes` 和 `yes+partial` 比例 |
| 原文证据覆盖 | 新路径提供的真实来源段落是否包含所需语境、关系或条件？这不改变正式记忆的留存标签 |
| 实际包充分性 | 真正传入该次生成的完整包是否足以回答？候选池里存在但未进入实际包的内容不计入 |
| 最终答案正确性 | 最终答案是否在原问题粒度上正确、完整，并保留必要限制？可答题与无答案题单列 |
| 协议与消耗 | 引用、审查、修订是否符合协议；分阶段记录实际请求、输入/输出/token/cache 与缺失 usage |

架构比较应复用冻结的来源、段落和正式记忆，在隔离副本运行问答，分别核对这些数据未变。旧实现与本轮实现使用同一批问题、同一冻结资料和独立登记的共同预算；最终配对审查应匿名并检查实际引用。没有完成真实模型运行和结果核验前，单元测试只能说明本地约束已被验证，不能证明正确率提升。
