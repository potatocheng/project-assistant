## 改动

| 问题 | 修复与边界 |
| --- | --- |
| 少量直接命中让邻接记忆和来源导航无法进入结果 | 直接候选耗尽后继续读取已合格的导航队列。邻接上限显式为 `limit / 4`，保持原调度可达到的配额：24 条最多 6 条；来源导航仍最多 `min(limit / 6, 4)`。无直接锚点不凭空扩展，项目、有效期、归档、冲突等资格检查不变。 |
| 部分回答中，已解决或未被询问的未知项又出现在自由文字缺口里 | 仅在完整通过协议校验后，排除与 `answered/unasked` 未知项同字面的 provider 缺口；只归一大小写、空白和句末问号/句号，不做语义猜测。固定义务派生缺口和同字面 `retain` 项优先保留；原始响应与未采用缺口均可审计。 |
| 删除答错对象的断言后，剩余部分依据仍被标记完整 | 义务的任何原支持断言被过滤，都重新降为部分回答或缺失，并保留所问目标缺口。其他义务不受影响；安全保留的断言不会被一起丢弃。 |
| 模型返回无效 JSON、截断或过滤内容时，已报告 token 丢失 | 在解析模型内容前把 usage 传给问答预算；保留原错误，并将实际报告用量计入本次累计和后续请求止损。成功调用只计一次，缺少 usage 仍明确标记不完整。现有阈值仍是服务商报告后的止损，不能当作调用前精确 token 上限。 |
| 跨检查点的同一候选只保留第一组引文 | 同一任务与快照、未编辑且仍待确认、关联草稿都为 ready 时，对通过原文校验的引文去重合并。正文、组织字段、状态和原始草稿不改；人工编辑、拒绝、确认、审核以及不同快照的提议不被改写。 |
