# 飞书资料与项目记忆

当前版本在侧栏增加“记忆中心”，分为飞书资料、空闲整理、待确认和整理记录。群消息与文档共用已有的原文、证据片段、候选、记忆和修订系统，按本地项目隔离。

## 使用顺序

1. 创建本地项目。在“飞书个人助理”保存应用凭据并完成个人 OAuth；仅采集资料时可以保持自动回复关闭。
2. 应用需有 `search:message`、`im:message.group_msg:get_as_user`、`im:message` 等消息读取权限，以及 `docx:document:readonly`、`wiki:wiki:readonly`。已有授权如果未包含新增文档权限，需要重新授权。企业管理员仍需批准权限、发布应用；个人账号本身也必须能访问指定群与文档。
3. 在“记忆中心 → 飞书资料”添加指定群 ID 和文档链接，为每个来源选择项目。可以加载自己可访问的群；文档支持 `https://团队.feishu.cn/docx/…` 和指向新版文档的 `/wiki/…` 节点。
4. 群首次回看默认 7 天，可设 1–30 天。保存来源并启用同步；默认每 300 秒同步一次，可设 60–3600 秒。“立即同步”安排后台任务，完成情况和失败原因显示在各来源下方。取消勾选同步并保存可停止后续采集，已经发出的网络读取可能仍会结束，失效结果不会入库。
5. 在“模型设置”配置模型。远程服务需明确允许发送资料；未配置时可采集和存档，整理会等待。飞书采集的正文不会受“手动导入资料自动提取”开关影响：它们统一等待空闲整理。
6. 默认停止应用内操作 120 秒后开始整理，每天最多 100 次整理模型请求。时间、额度及是否自动接受独立新事实均可修改；也可以立即整理一项。恢复备份后需要重新启用。
7. 冲突、语义相似但不完全相同、不确定内容进入“待确认”，侧栏显示数量。存在待确认冲突或不确定更新的目标记忆暂不参与自动问答，避免仍按旧结论代答。核对当前记忆、新内容、判断理由和双方原文后，选择采用新内容、另存一条、合并依据或忽略。内容可以先编辑。目标记忆已有更新时必须重新比较。

## 信息怎样获取

- **群**：使用个人 `user_access_token` 调用群历史接口，读取文字与富文本；补读话题，并用限定群和时间范围的消息搜索发现旧话题里的新回复，再批量读取正文。采集不要求 @你，也不要求 @助理。
- **文档**：读取新版文档元信息与纯文本。知识库链接先解析所指向的文档，不遍历知识库或跟随正文中的其他链接。读取正文前后核对版本号，期间发生编辑则下轮重读。
- **范围**：只读取启用且明确指定的来源。图片、附件、语音、卡片、旧版文档、表格与多维表格暂不解析。只读取知识库单个指定文档，不自动递归抓取其他页面。
- **时间**：群消息保留作者标识和发生时间；文档接口不提供作者与实际修改时间，因此明确标为未提供，以版本号识别变化，不把采集时间冒充发生时间。
- **增量**：群消息按 10 分钟会话片段存档，保留每条消息 ID、作者、时间和正文，给提取提供邻近语境，避免每条短消息单独调用模型。相同消息集合去重，片段变化保留新的原文版本；文档版本未变就跳过正文。群读取保留最多 15 分钟重叠，缓解搜索索引延迟。历史回看每轮最多推进一天，消息密集时自动缩小时间窗口，界面显示“已同步至”时间；下一轮从已完成范围继续。分页不完整或写入失败不推进游标，重读仍会去重。

群历史按消息创建时间增量查询，重叠窗口以外的旧消息编辑、撤回不会自动清除既有记忆；文档删除、正文中省略旧事实也不会被当成事实自动撤销。需要撤销的事实应明确修订或提供新的更正资料。搜索索引可能有延迟，首次真实接入应核对群内样本，自动化夹具不代表租户实际权限与搜索完整性。

## 记忆怎样更新

每次采集形成不可变原文快照，并记录远程标识、版本、链接、作者、发生时间及采集时间。原文解析成稳定片段，模型提取的每条候选必须带能逐字匹配的原文摘录。模型输出和助理自己的飞书回复不会成为采集依据；已记录的代答回执、相同代答正文、代答前缀和机器人消息会被过滤。

整理只比较该项目当前有效的记忆。模型收到候选、有限的原文摘录、来源时间/版本及当前记忆；不会把历史版本当作当前结论。

| 比较结果 | 处理 |
| --- | --- |
| 独立新事实 | 飞书采集来源可按设置自动加入；关闭自动接受时进入待确认 |
| 内容完全相同 | 飞书来源合并证据，生成内容相同的新修订，保留原有证据 |
| 意思相似 | 人工核对后合并依据、另存或忽略 |
| 同一事实的修改、更新、矛盾 | 等待用户确认，当前记忆继续保留 |
| 不确定或比较上下文装不下 | 等待用户澄清，不能自动认定为新事实 |

自动写入标记 `automatic`，界面显示“自动整理”；人工确认及用户纠正分别保留自身来源。采集原文、AI 提取模型/规则版本、证据和记忆修订可追溯。手动导入的候选仍然需要用户确认。模型判断可能出错，对自动入库要求更严时可关闭自动接受新事实。

## 空闲时做什么

后台优先比较未处理的 AI 候选，再提取新采集且已解析的资料，逐项推进。没有新增候选或资料时不调用模型，不定期重写全部记忆。失败的比较可重试，失败的提取可在项目资料中重试；用户编辑过的候选由用户核对。

空闲以应用内键盘、点击和修改操作判断，界面定时刷新不会算作活动。用户开始操作、修改模型/整理策略、取消任务或还原工作区后，未提交的结果失效。已经发出的模型请求可能仍会计费。只有整个提取成功且原文、任务代次与工作区快照仍有效，才提交候选。

每日预算按本机日期持久化，包含空闲提取的每个批次和语义比较的网络请求；本地判定完全相同或项目首条记忆不占模型请求额度。预算不包含手动提取、问答或飞书读取。到达额度后等待下一日；若单份长文超过额度中断，需提高额度并在资料中重试。还原旧备份不会退回本机已消耗的请求额度。

应用关闭、电脑休眠或网络不可用时不执行任务，不承诺全天在线。同步失败保留错误，资料不会因读取失败或模型错误而覆盖当前记忆。

## 保存与恢复

SQLite schema 升级到 4。`source_origins`、`memory_reviews`、`memory_runs`、整理策略及预算保存在项目数据库，随备份保留；原文仍在 `originals/`。旧版备份可迁移。

飞书凭据、个人令牌、来源订阅与同步游标属于本机连接配置，位于私有设置和 `feishu-runtime.sqlite`，不进入项目备份。还原时暂停同步与整理、清空采集游标；核对来源与项目后再启用，重新读取的原文按内容去重。记忆修订和既有来源记录不会丢失。

代码：`crates/core/src/feishu/knowledge.rs` 负责指定来源采集，`memory.rs` 负责来源、比较与确认，`maintenance.rs` 调度空闲任务，`src/components/MemoryCenter.tsx` 提供操作界面。

验证使用临时工作区和本机确定性 HTTP 服务，覆盖来源限定、话题补读、重复同步、文档版本竞态、分页/写入失败、自动新记忆、合并证据、冲突确认、过期版本、预算、活动中断与备份还原。真实飞书权限、个人账号和模型语义效果仍需配置后联调。
