# 飞书资料与项目记忆

本轮问答新增独立原文段落证据、完整证据包审查与最多一次完整答案修订。当前架构、引用身份、人工修订优先规则、容量预算和评测口径见[记忆问答架构](memory-architecture.md)。以下保留既有采集、整理与历史实现说明；新问答路径的行为边界以该架构文档为准，真实模型比较结果尚未得出。

当前版本在侧栏增加“记忆中心”，分为飞书资料、空闲整理、待确认和整理记录。群消息与文档共用已有的原文、证据片段、候选、记忆和修订系统，按本地项目隔离。

## 使用顺序

1. 创建本地项目。在“飞书个人助理”保存应用凭据并完成个人 OAuth；仅采集资料时可以保持自动回复关闭。
2. 应用需有 `search:message`、`im:message.group_msg:get_as_user`、`im:message` 等消息读取权限，以及 `docx:document:readonly`、`wiki:wiki:readonly`。已有授权如果未包含新增文档权限，需要重新授权。企业管理员仍需批准权限、发布应用；个人账号本身也必须能访问指定群与文档。
3. 在“记忆中心 → 飞书资料”添加指定群 ID 和文档链接，为每个来源选择项目。可以加载自己可访问的群；文档支持 `https://团队.feishu.cn/docx/…` 和指向新版文档的 `/wiki/…` 节点。
4. 群首次回看默认 7 天，可设 1–30 天。保存来源并启用同步；默认每 300 秒同步一次，可设 60–3600 秒。“立即同步”安排后台任务，完成情况和失败原因显示在各来源下方。取消勾选同步并保存可停止后续采集，已经发出的网络读取可能仍会结束，失效结果不会入库。
5. 在“模型设置”配置模型。远程服务需明确允许发送资料；未配置时可采集和存档，整理会等待。飞书采集的正文不会受“手动导入资料自动提取”开关影响：它们统一等待空闲整理。
6. 默认停止应用内操作 120 秒后开始整理，每天最多 100 次整理模型请求。时间、额度及是否自动接受独立新事实均可修改；也可以立即整理一项。恢复备份后需要重新启用。
7. 冲突、语义相似但不完全相同、不确定内容进入“待确认”，侧栏显示数量。存在待确认冲突或不确定更新的目标记忆暂不参与自动问答，避免仍按旧结论代答。核对当前记忆、新内容、判断理由和双方原文后，选择采用新内容、另存一条、合并依据或忽略。内容可以先编辑。目标记忆已有更新时必须重新比较。

## 信息怎样获取

- **群**：使用个人 `user_access_token` 调用群历史接口，读取文字与富文本；补读话题，并用限定群和时间范围的消息搜索发现旧话题里的新回复，再批量读取正文。采集不要求 @你，也不要求 @助理。
- **文档**：读取新版文档元信息与纯文本。知识库链接先解析所指向的文档，不遍历知识库或跟随正文中的其他链接。读取正文前后核对版本号，期间发生编辑则下轮重读。
- **范围**：只读取启用且明确指定的来源。图片、附件、语音、卡片、旧版文档、表格与多维表格暂不解析。只读取知识库单个指定文档，不自动递归抓取其他页面。
- **时间**：群消息保留作者标识和发生时间；文档接口不提供作者与实际修改时间，因此明确标为未提供，以版本号识别变化，不把采集时间冒充发生时间。
- **增量**：群消息按 10 分钟会话片段存档，保留每条消息 ID、作者、时间和正文，给提取提供邻近语境，避免每条短消息单独调用模型。相同消息集合去重，片段变化保留新的原文版本；文档版本未变就跳过正文。群读取保留最多 15 分钟重叠，缓解搜索索引延迟。历史回看每轮最多推进一天，消息密集时自动缩小时间窗口，界面显示“已同步至”时间；下一轮从已完成范围继续。分页不完整或写入失败不推进游标，重读仍会去重。

群历史按消息创建时间增量查询，重叠窗口以外的旧消息编辑、撤回不会自动清除既有记忆；文档删除、正文中省略旧事实也不会被当成事实自动撤销。需要撤销的事实应明确修订或提供新的更正资料。搜索索引可能有延迟，首次真实接入应核对群内样本，自动化夹具不代表租户实际权限与搜索完整性。

## 记忆怎样更新

每次采集形成不可变原文快照，并记录远程标识、版本、链接、作者、发生时间及采集时间。原文解析成稳定片段，模型提取的每条候选必须带能逐字匹配的原文摘录。模型输出和助理自己的飞书回复不会成为采集依据；已记录的代答回执、相同代答正文、代答前缀和机器人消息会被过滤。

整理只比较该项目当前有效的记忆。模型收到候选、有限的原文摘录、来源时间/版本及当前记忆；不会把历史版本当作当前结论。

| 比较结果 | 处理 |
| --- | --- |
| 独立新事实 | 飞书采集来源可按设置自动加入；关闭自动接受时进入待确认 |
| 内容完全相同 | 飞书来源合并证据，生成内容相同的新修订，保留原有证据 |
| 意思相似 | 人工核对后合并依据、另存或忽略 |
| 同一事实的修改、更新、矛盾 | 等待用户确认，当前记忆继续保留 |
| 不确定或比较上下文装不下 | 等待用户澄清，不能自动认定为新事实 |

自动写入标记 `automatic`，界面显示“自动整理”；人工确认及用户纠正分别保留自身来源。采集原文、AI 提取模型/规则版本、证据和记忆修订可追溯。手动导入的候选仍然需要用户确认。模型判断可能出错，对自动入库要求更严时可关闭自动接受新事实。

## 空闲时做什么

后台优先比较未处理的 AI 候选，再提取新采集且已解析的资料，逐项推进。没有新增候选或资料时不调用模型，不定期重写全部记忆。失败的比较可重试，失败的提取可在项目资料中重试；用户编辑过的候选由用户核对。

空闲以应用内键盘、点击和修改操作判断，界面定时刷新不会算作活动。用户开始操作、修改模型/整理策略、取消任务或还原工作区后，未提交的结果失效。已经发出的模型请求可能仍会计费。每个成功批次通过原文、任务代次与工作区快照守卫后，在短事务中保存检查点与草稿；校验通过的内容立即成为待确认候选。后续批次失败不会删除已保存内容，界面仍显示任务未完成及部分覆盖范围。

每日预算按本机日期持久化，只在空闲提取实际发请求前及语义比较请求前扣计；缓存复用与本地判定不占模型请求额度。该每日预算不包含手动提取、问答或飞书读取。手动及空闲提取还共同受每任务预算约束，失败、截断父请求及不明结果的在途请求都不能从任务消耗中消失。达到每日额度后等待下一日；单份长文中断后可在资料中恢复。还原旧备份不会退回本机已消耗的每日请求额度或同快照提取任务预算。

## 有预算的提取、草稿与审核

当前提取提示版本为 `project-memory-task-extraction-v6-literal`。正文优先采用一至两句完整原文表达一个事实，保持主体、代词、名称、数值、数学/LaTeX、大小写、否定和条件；可选组织字段再取正文与实际引文共有的字面片段。不能将正文的“We”改成“The authors”，却把“We”留作必须逐字匹配的主体字段；也不能格式化正文的数学符号，却保留原写法的条件标签。无依据的可选字段应在生成时明确为空，已经生成却校验失败的范围字段仍进入审核。

初始批次最多2400个Unicode字符；按段落和句子切分，长片段使用最多256字符重叠。每次提取的输出上限为6144 token，模型schema和Rust运行时共同限制最多12条记忆、4条任务、共16条候选；记忆正文/任务描述最多600字符，每条最多3处引文，每段引文最多800字符。超过数量或长度上限才触发容量错误；恰好达到上限仍可能成功，批次完成不能证明语义提取完整，须由后续信息留存评测检查遗漏。

可归因于容量的截断或越界在预算内最多拆分两层，拆分父请求保留状态和消耗；认证、限流、网络、内容过滤和无效JSON等错误不自动重放。每任务设置512次请求、累计300万实际报告与保守预留token的止损阈值，以及20分钟活动耗时。没有精确分词器：请求前按完整请求字符和输出额度保守预留，提供usage后记录实际输入/输出；缺失usage不记作零。请求前持久化在途请求的token与耗时预留，进程中断后恢复仍计入消耗。

| 校验结果 | 保存与处理 |
| --- | --- |
| 正文、来源或引文无效 | 不生成可确认候选；原始批输出及拒绝原因可追溯 |
| 仅topic导航标签不合法 | 隔离该标签，保留原值和原因；其他校验通过后生成待确认候选 |
| entity、role、conditions或validity不合法/冲突 | 原样保存为`needs_review`组织草稿，不生成可确认候选 |
| 全部校验通过 | 保存`ready`草稿与pending候选，等待对应确认流程 |

资料侧栏的“组织范围待审核”可核对原文，修改正文、主体、主题、角色、条件和日期并填写审核原因。审核通过只生成待确认候选；审核后仍须确认才能成为手动导入的正式记忆。原来非空的主体、角色或日期不能通过清空来批准，原条件不能通过删减、空字符串或重复占位绕过校验；无法修正时可填写原因并忽略草稿。引文逐字存在和字段字面校验仍不能替代事实语义核对。

成功批次、拆分关系、失败原因、原始模型输出及累计usage保存到`extraction_batches`，原始候选、组织字段、问题和审核轨迹保存到`extraction_drafts`。正式检索不读取这些草稿或pending候选。去重键包含正文及校验后的组织字段；正文相同但适用范围不同的候选不会互相覆盖。同一任务与快照内，重复候选会向尚未编辑或人工审核的待确认提议合并新的有效引文；原始草稿分别保留。已确认、拒绝、人工编辑或审核过的提议不随后续检查点改变。

应用关闭、电脑休眠或网络不可用时不执行任务，不承诺全天在线。同步失败保留错误，资料不会因读取失败或模型错误而覆盖当前记忆。

## 保存与恢复

SQLite 当前 schema 为10。`source_origins`、`memory_reviews`、`memory_runs`、整理策略及预算保存在项目数据库，随备份保留；提取新增`extraction_batches`、`extraction_drafts`和`extraction_budget`。原文仍在`originals/`，旧版工作区和备份按事务迁移。

恢复提取只复用同一资料哈希、片段快照、模型配置修订、提示与批次计划下的成功批次及已拆分父节点；显式重试不会再次请求成功批次，也不会重复建候选。任务失败后由用户重试，普通进程重启恢复先前未完成任务；取消任务保持取消。配置、提示或资料快照变化时启动新任务，原草稿保留原始来源。工作区epoch、任务generation及来源版本守卫阻止旧请求写入。

备份允许保存仍有无效原始字段的待审核草稿，但会核验可确认候选的依据和组织信息。还原暂停提取；手动恢复时，独立预算台账保留还原前同任务快照的消耗高水位。预算可以保留，已被旧备份覆盖的事实不会因此被当作成功缓存重建。

飞书凭据、个人令牌、来源订阅与同步游标属于本机连接配置，位于私有设置和 `feishu-runtime.sqlite`，不进入项目备份。还原时暂停同步与整理、清空采集游标；核对来源与项目后再启用，重新读取的原文按内容去重。记忆修订和既有来源记录不会丢失。

## 无向量问答检索

两个问答入口共用 `memory_query.rs` 的当前有效记忆筛选与BM25排序，检索版本为 `organized-memory-v12-sparse-context-fallback`。BM25在全部合格的项目记忆正文上计算词频、文档频率和长度，不把FTS的OR命中子集当成整个语料。每次查询核对当前修订、项目、归档、待确认冲突和显式有效期；本地扫描上限为10000条、32MiB正文。桌面另读取任务、里程碑等结构化记录，飞书继续只读取绑定项目的正式记忆。当前未引入embedding、语义重排模型或向量数据库。

`search.rs`共用常用中英文术语、全角及大小写归一化、英文停用词和保守词形扩展；精确拼写权重高于词形回退，中文保持字面检索。`corpora`按`corpus`的精确不规则复数处理，仍保留词边界，不匹配包含它的更长专名。明确英文实体按完整词边界绑定，`Ann`不会匹配`annual`；`we`、`the model`、`our approach`等泛指主体不建立专名范围，也不因主体标签不同排除其他记忆。具体实体不匹配仍被排除；原始组织字段完整保留，泛指或未标注记录不能因此被推定适用于某个具体主体。

只有项目、类型、完整正文和facets全部相同的重复正式记忆会在上下文中压缩；条件、角色、有效期或正反事实不同的记录不会合并。直接命中之间按“3条直接匹配、1条邻接记忆”交错补充，24条上下文最多6条邻接记忆。按直接匹配顺序选最多6个独立的ready来源与片段序号组作为锚点，相同片段的多个命中不重复占锚点。候选分配给距离最近的锚点，每组先取同段、再取相邻序号，并在组间轮流取项。对于同段候选，以当前正文在来源片段中的精确位置计算与锚点的前后间距，优先保留邻近定义和限定句；正文找不到精确位置时按词法分数、正文和facets稳定回退，不按随机UUID决定语义顺序。这些位置只影响已经确认的当前候选排序，不向模型增补未确认的原文。补充项仍须通过同一范围、当前修订、冲突、实体和时间检查。

泛指数据集、语料或训练数据的问题另保留少量同一ready来源的数据采集与研究背景候选，最多为`min(检索条数/6,4)`条，与直接命中交错，仍保留多数直接候选。来源候选识别明确采集或有命名、公开来源的语料使用与训练，并优先覆盖不同来源片段，再重复同一阶段。来源关系检查首个`from/via/来源`前的对象；提升分数、角色标签或参数采样、潜变量生成不能因后文提到数据而占用来源导航位。已有计数采集、公开来源、字面数据提取及中英文采集路径保留；第一人称`run/conduct/perform experiments on/using`命名数据资源也可作为使用来源。计算分数、特征或向量仍不算数据来源。显式专名绑定或组件、编码器、解码器、分类器、子模型等明确目标不走该补充路径。`data_provenance/study_context`只是导航线索，不代表系统已经判定所问主任务；章节目录、其他研究和未来计划不能冒充当前数据采集。生成与审查仍须区分主研究、组件、相关工作和实验阶段，不把子模型的数据量或指标推广成整体。上述规则只改变既有候选的导航选择，不扩大候选池，导航位及总上下文容量未增加。

FTS5是派生导航缓存，保存中文字符/二元词、英文词及词形；后端版本为`fts5-derived-v3`，内容标记为`lexicalschema3`。旧标记（包括`lexicalschema2`）、缺失索引或修订变化会触发重建，备份还原后同样重建；缓存不能决定事实资格，也不是答案依据。普通版本映射表提供主键查询，但每次仍有有界资格和目录扫描，并非恒定时间检索。

模型上下文按`current-content-pack-v2-indexed-spans`组装，容量按白名单投影后的参考内容计算，原始引文与完整record不挤占模型正文预算。飞书`confirmed-current-memory-v8-target-obligations`最多24条、36000字符；桌面`personal-assistant-v9-target-obligations`聚焦问题最多24条总参考、36000字符，概览最多40条、40000字符，其中正式记忆最多24条，其他类型仍分别有界。桌面正式记忆保持共享检索顺序，不按共同来源标题重新排序。

生成模型收到本次当前`content`的编号连续片段：`referenceIndex`与`spanIndex`均从1开始，每片段最多600个Unicode字符，优先在句末或换行处分界，拼回后逐字等于本次供给的完整正文，空白也不丢失。这是确定性切片，不是摘要或关键词选择。模型只输出简洁断言和`supportSpans`编号，不必反复抄写UUID、引用并集与quote。Rust根据可信引用列表恢复原ID和逐字锚点，再校验越界、重复、引用数量、长度与当前版本；编号绑定本身仍不证明语义正确。

配置可用且获准访问资料的模型后，`question_flow.rs`对每次模型生成的grounded回答都发起独立证据核验，包括单条完整正文直引。`claim-support-v8-explicit-claim-indices`先列出1至6条所问义务`obligations:{target,status,claimIndices}`：`answered`表示完整覆盖该目标，`partial`表示直接覆盖必要部分，二者须绑定现有断言索引；`missing`必须没有断言索引。义务及回答粒度只由原问题决定，unknowns或参考资料不能扩大问题：总体或是否类问题不自动要求逐组枚举、量化汇总，询问指标不自动要求所有分项，询问机制不自动要求维度、批处理或复杂度，询问某组人数不自动扩大为全研究人数。显式询问的对象、基线、关系或方法仍须回答。`answersQuestion`须与至少一个义务被直接覆盖一致，背景或其他对象不能充作所问答案。审查看到所选支持片段及被引用记录的完整当前编号正文；其他片段只帮助核查限制条件，不能代替选错的锚点。输入不重复传输已渲染答案和相同quote。

每条原始unknown必须在`unknownDecisions`中按从1开始的索引恰好处理一次：`retain`保留必要未知，`unasked`标明未问细节，`answered`表示已有断言确实解决；后者必须绑定已被完整回答义务采用的断言索引，前两者不能带断言索引。`completeAnswer=true`要求全部义务为`answered`、全部断言有据、没有retain项且`missingAspects`为空；汇总标志本身不能批量删除unknowns。缺失或部分义务必须留下必要缺口，不能把明确询问的对象、比较基线、参数共享关系或计算方法当作未问细节。原始保留项加新增必要缺口超过6项答案上限时，新增项的溢出部分记录到`qualityReview.unrenderedMissingAspects`，仍保持partial并供补查读取，不静默丢失或挤掉原项。

审查输入为每条已校验断言显式标注从1开始的`claimIndex`；输出的`claimIndices`只能复制这些编号，其schema枚举限定为本次实际1至N，不能误抄`referenceIndex`或自行编号。越界和重复编号仍严格拒绝，不通过重映射放行。

仅当审查结构合法、断言有据且直接回答、`completeAnswer=false`，并且粗粒度义务虽全标成`answered`却仍明确保留必要unknown或`missingAspects`时，程序保守接受为`partial`，不推断完整或清除保留项。原始审查存为`rawReview`，同时记录`effectiveStatus=partial`和`normalization=coarse-answered-with-explicit-gaps`。这项归一化不放宽索引、逐unknown处理及断言支持检查；`completeAnswer=true`与保留未知或缺口矛盾仍拒绝。

泛指模型、数据集、单体与联合、组件或比较关系等问题的审查，最多另带2条当前可见但未被答案引用的范围导航，每条正文最多220字符、整个`scopeCandidates` JSON最多1800字符，并明确标为`notSupport:true`。它们经过项目和来源标题约束，只帮助识别主次对象混淆，不能支持新断言、修复错误锚点或替代正式引用。结构化字段直读及未启用模型的本地回答不经过该模型核验。

Rust保证索引、逐项覆盖、数量、一致性及当前快照校验；目标拆分是否正确、unknown是否确属未问、主任务与组件是否对应，以及事实的语义支持仍由模型判断，可能出错。不能把协议校验通过当作语义可靠性证明，仍需真实题集和独立人工复核。

初次回答未知、部分覆盖、只有相关背景或被语义审查否决时，最多进行一次定向补查。改写模型收到原问题、已知缺口和当前可见记忆的短目录，输出最多3个、各2至160字符的检索词组。目录最多24项、4000字符，保留记忆ID、修订和正文前100字符标签，不重复完整facets；按主体、事项和类型分组轮取，优先词法命中的组。标签只作导航，不作为证据。补查仍按同一范围重新检索，再生成并核验最终回答。若问题、项目、日期、偏好、范围和版本等生成信封字段相同，且参考按非空稳定ID对应的完整`model_reference`投影逐项相等，单纯重排也可记录`UNCHANGED_CONTEXT`并跳过第二次生成和审查。缺失或重复身份、正文或条件等投影变化不能按相同处理；跳过前仍校验初次及当前两个完整快照，并保留初次答案的原引用映射，不按新顺序重新绑定。改写词不进入生成信封，避免相同证据反复生成。审查传输失败或返回格式不可用时停止，不把服务错误当作知识缺口继续补查。目录与改写不能指定项目、执行SQL、打开网址或写入数据。

初次已经通过引用和语义审查的grounded partial可作为一次补查的安全回退。补查生成、审查或预算失败且最终无有效答案时，只能取回这份原答案，不能放行新出现的未审查断言；返回前重新验证初次与当前两个快照，任一过期仍取消。原答案不是已获审查通过的部分回答时，失败仍拒答。

`bounded-question-flow-v6-explicit-claim-indices`每题最多5次模型请求，累计请求消息及输出schema最多180000字符，每次解析结果最多16000字符；典型上限为首次生成、首次核验、定向改写、再次生成、最终核验。整次模型阶段沿用设置中的同一超时时间，各次请求使用剩余时间，无自动网络重试。严格JSON-schema服务只在provider字段传一次schema；JSON-object模式在用户输入中保留一次，避免重复提示。`queryTrace.stages`记录各请求耗时及服务商提供的实际输入/输出token；未提供usage时标为缺失，不估成零。累计已报告token达到60000后停止追加请求；这是响应后的止损阈值，不是精确分词后的请求前硬预算。补查与核验前后检查工作区和配置版本，最终回答再次校验当前记录。

`queryTrace`记录各轮候选ID、分数、`direct_lexical/adjacent_confirmed/data_provenance/study_context`选择原因、精确重复压缩数量、改写、请求与输入字符及各次审查；模型grounded回答包含`qualityReview`。`answerGenerationIndex`从0开始指向实际返回答案的真实生成，`reviewedPartialFallback`标记是否回退初次部分答案；失败或预算阻止第二次请求时不能伪造生成记录。补查错误码与全部审查历史保留。这些是诊断数据，业务记录不因问答改变。本轮实施与门槛见[问答校准计划](memory-qa-calibrated-plan.md)；此前高效轮及检索实施分别见[QA高效轮计划](memory-qa-efficient-plan.md)和[检索优化计划](memory-retrieval-optimization-plan.md)。

## 项目工作简报

在项目总览选择项目，点击“生成简报”。简报按目标、进展、已确认决策、阻塞与待决策、建议跟进的现有任务、最近记录组织，保留对应记录、版本、时间和原文引用。待确认候选单独展示，存在冲突的旧记忆沿用问答的排除规则。已有的任务负责人、日期、依赖和管理事项关联继续作为结构化依据。

简报使用本地规则，不调用模型。`project_briefs` 保存生成时的检索上下文、检查日期、范围版本摘要和指纹，每个项目保留最近一次生成结果。目标、资料、任务、记忆、依赖、跟进、排期、管理记录或待确认内容变化后，旧简报显示过期提示；切换检查日期也需更新。展示有数量上限，完整任务仍需打开项目核对。“建议跟进”按已有阻塞和期限排序，不自动创建任务或执行动作。

简报是派生视图，不参与正式记忆提取，不被当成新增事实，也不以摘要替换原文。日期用于评估当前记录，不是还原该日历史。

## 纠错与质量反馈

手动修订记忆时，`memory_corrections` 在同一事务保存旧/新版本、旧/新正文、修订理由和可选的真实问题；未填问题时生成包含原内容的核对问题。迁移旧工作区时也会补入既有人工纠正记录。

记忆中心“质量反馈”可以检查最近最多 200 条纠错样本。检查调用飞书记忆问答使用的本地检索，验证对应问题是否召回该记忆的当前修订；已有后续修订的旧样本跳过。问题没有匹配当前正文、存在待确认冲突或上下文容量限制时可能不召回。检查不调用模型；结果仅在本次界面显示，不代表回答语义正确，也不衡量提取准确率。

同一页面提供人工提取抽检：

- 对未经人工编辑的 AI 记忆、任务候选核对原文，标注内容、负责人、日期、状态、依据问题或正确。
- 对已解析的资料记录漏提，并在说明中写预期内容和原文位置。
- `extraction_assessments` 保留候选快照、来源、模型/提示版本和标注理由，同一快照重复提交更新标签，不增加样本数。后续人工编辑候选不会改写原来的抽检快照。
- 页面统计全部已标注样本，展示最近 100 条记录。样本存在选择偏差，不能当作全项目准确率，也不会自动训练模型或修改提取规则。

后续优化应据这些样本复现具体错误、调整检索或提取规则，再重新抽检。人工纠正正式记忆后，问答只使用最新版本；抽检中的旧内容只用于回顾。

## 明确填写的个人偏好

项目问答的“个人偏好”保存职责说明、回答详略、日报格式、问答跟进措辞。职责仅供启用模型时组织重点参考；本地回答详略控制展示条数，跟进措辞用于本地跟进回答。日报生成时冻结所选格式，以后修改偏好不改变已保存的日报。偏好带版本校验，修改期间的过期模型回答会被拒绝。

偏好不会从聊天猜测，也不用于认定个人身份或自动分配任务。它们不进入飞书代答上下文。用户主动启用模型问答时，会随已选项目上下文发送给已授权的模型服务。

点击“清空偏好”恢复默认并删除当前职责文本；既有备份仍可能包含旧偏好。偏好、简报、纠错和抽检均保存在 SQLite 并随项目备份保留，ZIP 未加密。备份还原检查版本、指纹、项目范围和引用关系。实现入口：`crates/core/src/memory_workbench.rs`、`src/components/MemoryWorkbench.tsx`。


## 按修订组织事实与回答断言

`revision_facets` 保存当前断言的 `entity/topic/role/conditions/validFrom/validUntil`；`proposal_facets`保存已通过校验、尚待确认的组织信息。主体、事项和条件必须在当前正文中逐字出现；AI候选还须在实际引用原文中出现。角色明确区分负责人、审批人和联系人，有效期只能使用正文明确写出的YYYY-MM-DD日期。字段不足时保留未知，不从发生时间推定有效期。模型已生成但校验失败的适用范围字段保留在待审核草稿中，不按未知字段放行；仅导航标签可独立隔离。

候选确认前显示组织信息；修订对话框可编辑这些字段，连同正文保存为新版本。修改正文不自动继承旧组织信息；仅合并依据且正文相同时可以保留。问答按已确认的主体及显式有效期筛选；未标注记录仍可搜索，但不能自动推定适用于某个主体。修订历史与组织信息一起备份；派生索引在备份私有快照中清空压缩，还原后重建。

模型回答采用 `answer_contract.rs` 的紧凑断言协议：输出`grounded/status/claims/unknowns`，最多12条结论；每条`claims`含`text`与`supportSpans:[{referenceIndex,spanIndex}]`，最多12个不重复片段及6个引用。模型不生成UUID与quote副本，Rust展开为对外的`text/citationIds/supportQuotes`，每个引用须绑定当前正文的逐字锚点，顶层引用恰好为断言引用的去重并集。最终正文由已校验断言与编号渲染，当前绑定版本为`indexed-current-spans-v2`；保留的内部旧锚点调用使用`atomic-anchors-v1`，不接收自由文本作为成功答案。桌面聚焦问题最多24条参考、36000个投影字符；概览最多40条、40000字符，其中记忆最多24条，非记忆类型分别最多6条或概览20条。引用语法和锚点存在不等于语义正确。

`answer_contract::model_reference`先将记录投影为白名单：当前`content`、`id/memoryId`、标题、来源标题、类型、项目、修订、更新时间，以及已接受的`facets`。`indexed_references`再把本次正文完整切为编号片段，去除空组织字段、重复标题、生成阶段的修订和更新时间。只有`memoryId`非空且`id`精确等于`memory:`加该ID时才省去重复`memoryId`别名；其他ID组合保留。同一参考列表全部具有精确相同且非空白的`projectId`时，仅首条显式携带项目，后续按首条继承；在此基础上，全部`sourceTitle`也精确相同且非空白时，来源标题同样只保留首条。混合、空或缺失项目不继承项目或来源，来源标题不一致时不省略来源标题。原本缺失的项目和来源标题在模型投影中显式置`null`，避免被误认为可继承。稳定ID仍由可信程序保留用于绑定和审计，模型输出只选择整数索引。语义审查补入更新时间，同时提供当前完整编号正文和已选片段。原始`evidence`、整条`record`和其他嵌套内容不进入这两类模型输入，避免模型把尚未形成正式断言的来源细节用作可回答事实。投影省略不改变运行时原引用、正文、条件、项目与版本校验；返回给界面和审计的完整引用仍保留原始依据和记录，原文入口不受影响。当前上下文容量按模型投影计数。

状态分为 `answered/partial/unknown/conflicted`。部分回答保留直接覆盖至少一个所问目标的可核实断言，单列 `unknowns`；缺失负责人不得用审批人代填。原始unknowns最多6项、每项2000字符，完整保留给语义核验及补查；`unknownsPresentation`与渲染正文每项最多300字符，超长显示省略号。展示裁切不能改变审查、部分回答或拒答判定。所有模型grounded回答都进入语义核验，单条完整正文直引也不例外；只有相关背景而没有直接答案时拒答。核验使用同一模型的另一次请求，仍会误判，新结论未通过时不能输出。

当模型返回`answered`但同时列出合法`unknowns`时，先在断言、引用并集、锚点、数量和长度校验全部通过后规范成`partial`；已知断言和原始未知项保留。之后必须逐项通过`unknownDecisions`，并且全部所问义务已回答、支持与完整性汇总一致、没有必要未知或缺口，才能转为`answered`，仍重新运行原有锚点和引用校验。`completeAnswer`不能独自清空未知项；该处理不补写事实、不放宽绑定，也不把无答案或协议错误转成成功回答。

### 历史问答目标与补查控制（qa-targeted，2026-10-21）

该轮实现采用`bounded-question-flow-v9-necessary-navigation-and-target-correction`与`claim-support-v11-literal-asked-mechanism`，替代上文描述的v6/v8控制协议。提取、组织存储与检索排序保持上一轮实现；此次改变发生在QA入口的语言导航、生成参考投影、语义审查和追加检索控制层。开发门槛、独立累计预算和比较对象见[本轮计划](memory-qa-targeted-plan.md)，失败开发后的实质修复分别见[第二次开发记录](memory-qa-targeted-v2-changes.md)、[第三次开发记录](memory-qa-targeted-v3-changes.md)与[最后一次开发记录](memory-qa-targeted-v4-changes.md)，实际结果以真实运行工件为准。

`question_target.rs`从原问题识别明确对象和所问关系，再从本次可见的当前正文中选择有限的逐字对象见证，作为`targetPlan`交给生成模型。标题、共现和泛指“模型”不能证明主任务身份；同名组件、单体、联合模型、以往工作仍需分别核对。只有明确答错对象或字面矛盾才由本地守卫降级，无法判定时保留未决，继续依赖正常语义审查。比较基线可以属于另一类模型，引用前人的方法也可以描述当前模型。

首次生成的对象投影仅对明确单一单体/联合目标生效：已有兼容字面见证时，排除整条只描述相反对象的参考；混合、不明、条件及比较关系完整保留。两个入口与控制器共享实际投影，索引归一化按本次真正供给的参考执行，原始上下文及快照不变。若首个有效审查后仍明确答错对象，且原先实际供给包中有未引用的兼容见证，可在真实本地检索与双快照校验后，用最多6条完整原参考组成不同的子集，追加生成和完整审查一次。此为对象纠错，不冒充发现新事实；原必要未知逐项进入第二审查，不能随新generation遗漏。

当前投影也保留显式包含被问单体成员的整体关系正文，供模型核对称谓和关系；不能把整体组成当作单体组成。明确问顺序机制时，QA入口可用`sequence order`进行本地语言导航，原问与项目、日期不变，显式检索计划不被覆盖；不增加模型调用，导航词不能成为事实依据。对于机制原问中有区分度的明确必要关系，provider将对应未知误标unasked时，本地守卫保留该未知并降级有效完整性，同时保留原始provider意见和独立守卫原因。未问内部维度、批处理等不因此扩大为必要义务。

新审查schema不再要求模型重复输出`answersQuestion/completeAnswer`。模型逐项返回义务状态、断言索引和unknown裁决；Rust按这些结果推导汇总状态，并分别保存`rawProviderReview`和`derivedState`。索引、逐项覆盖和必要未知校验仍然严格；兼容旧格式时，两项汇总布尔仍需成对并一致，旧失败结果不作追溯修正。去掉重复字段降低格式自相矛盾的机会，不代表语义审查不会误判。

常规路径为一次生成加一次审查。已获审查的部分回答只对原问题明确要求、仍未解决的缺口作本地定向补查；未问细节和无法确认是否必要的unknown不触发自动补查，也不会被控制器静默清除。最多3条检索词优先保留缺口，原问题仍随检索请求携带。只有补查带回新的当前正文事实，且有对应缺口关系见证时，才追加一次生成和审查；换ID、来源或修订但事实相同不算新事实。缺口见证只准许再次核验，不能直接升级为有答案。

有效、有据且直接回答必要部分的partial在本地补查无新正向见证时，还可使用一次目录导航改写，再作第三次真实检索；仍须找到新的、匹配明确缺口的当前事实，才追加生成。缺口使用原问语言及原文术语，目录和改写都不能支持事实。普通unknown、未问或未决细节、格式及传输失败不使用这条partial导航路径。该分支与对象纠错互斥，整题仍最多一次追加生成、5次模型请求与3个真实检索轮。

初始参考为空时，先尝试本地检索；仍无可用内容才允许一次目录驱动的LLM改写，保留口语问题找到旧记忆的路径。已得到部分答案不会为未问细节调用改写模型。整体仍受最多5次请求、180000输入字符、每次16000输出字符、同一总超时和服务商报告token止损阈值约束。无效JSON、截断和过滤响应中已报告的用量也计入累计；没有usage时明确标记计量不完整。经过审查的旧partial可以在追加阶段失败时安全回退，返回前仍重新验证原始和当前快照。

`queryTrace.generationRounds/reviewRounds`明确记录实际生成、审查与检索轮的对应关系，不再按改写次数推算。`supplementDecision`保留缺口分类、本地检索词、新事实与见证、停止原因；协议错误与安全回退分别计数。问答仍为只读，不把评测gold、历史正确答案或来源原文中的未组织细节输入生产回答。

## 固定义务、证据关系与增量回答（qa-structured）

直接命中耗尽后，检索会继续读取已通过资格检查的邻接与来源导航候选，不再因未到原交错槽位而提前结束。邻接额度保持每四个结果一个槽位，24条最多6条；没有直接锚点时不作此扩展。此次可靠性修复与本地验证见 [后续修复记录](memory-reliability-followup.md)。

原始问题先经过 `question_plan.rs` 生成固定 `o1…o6` 义务。仅显式第二问拆分，模型名称、数据集和举例列表不自行变成新问题；超过六组时保留整句，避免丢失问题内容。生成与审查复用同一计划。断言和未知项分别以 `c1…`、`u1…` 定位，审查逐条返回支持、对象不符或无支持，以及保留、未问或已回答。完整性由程序结合这些结果计算。固定问题均已回答时，自由文字缺口只记录供审计；必要未知项仍必须单独处理。

稳定协议允许单独保留已明确审查且直接回答问题的断言，并重新生成引用编号。协议缺项仍标为 `QA_REVIEW_SCHEMA`，记录原始响应，保留必要未知，停止补查；安全保留部分结果不能算作协议通过。局部对象守卫逐条排除明确回答其他模型或任务的断言，正确断言不能为同一回答中的错误断言提供信任。义务的任一原支持断言被过滤后，该义务降为部分回答或缺失，保留所问缺口，不能只凭剩余断言沿用完整结论。

局部未知项的解决与整题完整性分别判断：宽问题仍有其他缺口时，一个未知项可以由同一必要义务下已支持、已保留的断言解决；整题仍须全部义务已回答、没有保留的必要未知才算完整。完整通过协议校验后，自由缺口中与已解决或未问未知项同字面的内容不再重复加入答案或补查，原文记录在审计中；必要固定义务和明确保留项不因此删除。对象守卫删掉错误断言后，如果汇总行漏列了另一条逐项审查已支持、且映射同一义务的正确断言，只恢复为部分回答，保留原问题缺口。只有这种本地恢复产生的概括缺口、没有模型明确审查的必要缺项时，不额外调用检索改写模型。

`memory_links.rs` 从合格当前记忆和现有来源证据重建导航关系，绑定修订、正文哈希和来源位置。字面关系须同时出现在当前正文与原文。邻接关系只用于导航，不作为事实证明；未新增数据库表或向量索引。`memory_query.rs` 最多返回64条本地候选，`evidence_pack.rs` 保留首条合规排名锚点，再按问题、关系覆盖和来源多样性选择完整参考。聚焦模型输入仍最多24条、36000字符，条件与正文不因覆盖排序而被裁掉。

组包先选出得分最高的候选，再用实际索引化 JSON 精确计算容量；超限则排除该候选后重新选择。来源距离、字面连接和重复度采用增量缓存。测试保留原始逐候选计算版本，对照所选引用、顺序、选择理由、覆盖及逐步字符数；64候选选24条的精确投影次数由超过1000次降至24次。字符上限继续依据实际完整投影，不使用估算值放行。

候选池及选择原因保留在本地上下文中，两个问答入口均校验其当前快照；候选池和导航图不直接送给回答模型。已经通过稳定审查的部分答案遇到必要新证据时，第二次生成只补缺少的义务。旧断言仅作为一致性和去重提示，不能冒充新增证据。增量必须经过明确的一致性审查，再分别核验实际引用并合并；失败时返回仍有效的旧部分答案。

综述问题可以从正文明确的章节引言继续向后导航，在最多六段窗口内保留前四个有正式记忆的段落组。每组最多选择两条完整事实，兼顾定义、方法或效果，另保留一条引言；这些内容替换低排名背景，继续共用64候选、24条参考和36000字符上限。分组绑定来源位置与修订，只作导航，不推断系统身份，也不把未确认原文拼成事实。泛指当前数据资源的属性问题可根据正文中明确的创建、引入或使用关系优先定位资源；明确命名、比较或多个当前资源时保留原范围和歧义。导航提示先检查全部本地候选，再只展示实际已选引用中的正文见证，避免子集漏掉另一资源后被误认为唯一，也不会把未选正文作为额外证据发送。

综述生成可附带最多900字符的 `surveyCoverage`，仅列出本次实际参考数组中的目录与段落组索引，不包含新正文、来源标题或“已完整覆盖”的判断。审查阶段按其实际引用子集重新编号，不能复用生成包的索引。默认回答本文综述的代表方法及有据角色，区分被综述工作与本文贡献；明确要求穷尽清单时保留该要求。分组不证明角色、未知已解决或整题已完整，程序继续使用逐条审查结果。

生成与审查共享原问的粒度、是否问句形式和显式范围。未限定的计数保留已记录群体条件，指标保留其平均值／聚合定义，联合训练机制不自动扩成每个组件的单独训练过程。程序不凭这些标签直接删除未知项；必要未知仍须逐项审查。没有列出输入不等于没有使用，独立组件也不直接证明共享或不共享权重。

`answerGenerationIndices` 记录最终答案的实际生成来源并集；`answerClaimProvenance` 将每条最终断言绑定到原始生成和检索轮。返回未知或拒答也保留实际生成上下文；没有发生生成才记为空。评测检查每条引用来自相应生成实际看到的片段，并分别报告单次上下文和最终多轮来源并集。调用、时间、累计输入、当前版本、项目范围和引用锚点限制继续生效。

本轮先做固定938条正式记忆的新旧二进制对照，再做重新提取的20题完整链路。固定记忆对照中的实际证据包可以不同，因此只能分析整个问答阶段收益，不能单独归因于生成模型。完整100题仅在预登记门槛全部通过后执行。复现命令见 [本轮命令](memory-qa-structured-commands.md)，预算与阈值见 [登记](memory-qa-structured-preregistration.json)。
