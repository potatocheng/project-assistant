# 项目管理：闭环、变更验收与协同

从侧栏打开“项目管理”，切换“风险、问题与决策”“需求变更与验收”“周报与会议准备”。上方可选择项目和检查日期；全部项目可查看台账，新建事项需指定项目。各页面无需模型密钥。

## 风险、问题与待决策事项

记录事项类型、责任人、影响级别、影响说明、处理方案、处理期限、复查日期和升级对象。到期、复查、升级或关联版本变化会提示关注；高影响未结事项和待拍板事项也会出现在全局管理提示和项目总览。

每次保存及独立进展记录均保留版本、业务日期、录入时间和说明。关闭必须填写处理结果和关闭原因，待决策事项还需拍板人及结论。关闭后的事项需先重开再处理，历史结果保留。

可以从已确认风险或决策记忆起草表单，再核对并保存。关联任务、里程碑、记忆和原文必须属于同一项目；关联版本更新后需复核，不能把旧依据默认为新内容。来源记忆不会被管理事项自动改写。

## 需求变更

记录变更前后、提出理由、提出人、决策人及范围、排期、工作量影响。审批信息由你核实后录入，审批与实施分别保存：草案提交后进入待审批，批准后还需记录实施结果。

修改变更内容会重新进入草案，原批准不会自动适用于新内容。提交和批准前核对关联版本；实施记录可保存执行后的当前版本，保留原审批依据。批准本身不会自动更改任务日期或里程碑，具体调整仍通过原有任务和排期流程确认。

## 交付验收

为交付物选择实际任务或里程碑，填写负责人和逐项验收标准。每项标准记录待核验、通过或未通过，填写核验依据及说明。发起验收后，由你核实并记录验收人、日期、结果和整改要求。

只有所有标准通过且有核验依据、实际任务已完成或里程碑及关联任务已完成，才能记录验收通过。验收失败保留整改事项。通过后交付目标或版本发生变化，会提示重新复核；旧验收仍保留为历史记录，不会被当成新版本的核验结果。

变更及验收均保留不可变修订与来源快照。取消草案会保留审计记录。已有任务完成状态与验收状态分别表达。

## 周报

选择起止日期及项目后生成本地周报。任务部分使用业务日期在区间内的进展和截至截止日的任务版本；本期成果要求期间内有实际完成事件且截止日保持完成，早前完成后仅改名的任务不会计为新成果。

风险、问题、待决策、变更及验收使用截止日的历史修订；已验收目标在截止日前重新打开时会提示复核。里程碑与依赖当前未保存完整历史，因此明确展示为生成时当前快照。

报告保留原始依据、来源 ID、版本与时间。编辑正文创建新版本且不改依据；重新生成会采集新依据并创建新版本。可查看旧版本、复制和导出 Markdown，桌面导出使用保存对话框。保存后的周报不会被之后的任务变化悄悄改写。

## 会议准备与行动项

建立会议并填写项目、日期、参会人和目标。生成会前材料会保存议程及简报，带出同项目此前会议的未结行动、阻塞及待决策事项，并保留生成时的依据。

会后记录纪要、结论和行动项。行动项必须明确负责人和期限，记录本身不会创建任务；逐项点击“确认并创建任务”，选择“跟进交付”或“亲自执行”后才产生正式任务，重复确认仍关联同一项。任务的当前负责人、期限和进展会反映到行动台账，同时保留会议原约定；会议旧正文仍保留。

会前材料和周报仅整理本机已记录内容，不自动发飞书消息或替他人作出决定。

## 数据与验证

schema 7 在同一事务中新增治理、变更验收及协同表。原有资料、记忆、任务、排期与 P0 数据保留。新状态、历史修订、原文关联和报告快照进入一致工作区备份；恢复前校验日期、版本链、项目边界及引用，失败不替换当前工作区。

验证入口为 `cargo test -p project-assistant-core --locked`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo fmt --all --check`、`npm run build`，以及既有四组 `verify:restart`、`verify:ai`、`verify:workflow`、`verify:planning`。专门的 `p1_integration` 测试覆盖新管理记录与总览、提醒、问答、报告、迁移及备份恢复的连接。

2026-10-19 验证结果：152 项 Rust 测试及四组真实进程流程通过，前端构建、桌面 Clippy 与格式检查通过。补充覆盖审批/验收历史篡改拒绝、验收日期与实际完成日期一致、行动项改派延期后的问答及会前快照。隔离工作区页面验收已走通风险进展、变更提交审批、交付验收、周报生成、会议准备与行动项转任务。Windows 调试测试版由 Tauri CLI 打包内嵌前端，输出于 `output/项目助理-P1-Windows测试版.exe`。
