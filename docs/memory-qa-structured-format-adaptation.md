# Structured QA evaluation format adaptation

This is a new independent evaluation round. All prior round manifests, reports, thresholds, raw provider responses and fees remain immutable.

- The production protocol may return incremental claims from two actual generation calls. New capture accepts only explicit `answerGenerationIndices` (zero based) and `answerClaimProvenance` with one based final/source claim indices, zero based generation/retrieval indices, raw text equality after only the existing production trim of leading/trailing whitespace, exact final/provenance text equality, and exact support span bindings. Legacy singleton producers use the old mapping.
- Unknown/refusal answers with an actual selected generation retain that generation as a producer even when the final claim list is empty; no generation means no producer. This preserves equal evidence assessment for old singleton and new incremental responses.
- Retrieval judge input contains only the union of actual selected producer contexts. It is not one model pack: each real generation independently retains the 24 reference / 36k character cap. Unselected failed attempts do not supply evidence.
- The dedicated judge adapter copies the existing three separated judges. Its only system prompt change replaces “the LAST actual generation references CONTENT” with “the actual selected producer generation references CONTENT (possibly multiple contexts that jointly produced the final answer)”. Answer criteria, all labels, anonymous system order, human gold, parsing and memory judge remain identical. New adapter hashes are captured before live execution. Old judge files remain unchanged.
- A frozen confirmed-memory diagnostic executes the preserved old binary and the current candidate binary on distinct SQLite copies of the same confirmed content, facets, revisions and source provenance. The baseline arm runs QA now and has no judge calls; the candidate arm grades both fresh systems anonymously using the same dedicated adapter. No historical answer is borrowed as the diagnostic baseline.
- Frozen memory does not freeze the supplied reference pack. Different retrieval/packing outcomes are measured separately with actual reference IDs and hashes. Offline pack comparisons cannot establish a fixed-pack causal effect.
- Diagnostics and every failed fresh development run share the newly registered 1200 request / 6M token development budget. Up to three fresh full-pipeline 20 question attempts plus at most one diagnostic pair are permitted. Full100 has a separate 2000 request / 12M budget and requires all registered development gates.
- Trace-derived obligation coverage, claim target status and unknown decisions are diagnostics, not independently human-reviewed truth. QASPER human labels and provisional same-model grades remain visibly separate.
