# 项目交付、提醒与统一问答

## 项目总览

从侧栏打开“项目总览”，选择全部项目或一个项目。维护目标、项目状态及目标日期；创建里程碑并关联同一项目内的任务。原定日期与当前预计日期分别保存，显示日期差异。预测日期由用户填写，系统不推测承诺日期。

项目关注状态根据当前任务、未满足依赖、具体阻塞、逾期、里程碑日期和项目目标日期计算，并展示判断依据。这是基于现有记录的提示，不是完整风险评估，也不通过平均任务百分比虚构项目完成率。取消的前置任务不等于交付完成。

关联任务全部为完成状态后，才允许将里程碑标记完成；取消任务需要解除关联。完成后任务重新打开，会再次提示复核。修改使用版本校验，遇到冲突先刷新核对。

## 提醒与跟进

提醒针对尚未完成、未取消的任务：截止日期已过；今天或未来三天到期；进行中任务或跟进任务至少三天没有进展；已到用户约定的下次跟进日期。

打开应用后，即使停留在其他页面，也会每分钟读取今天的提醒，显示侧栏数量和跟进横幅。回到应用会再次检查。收起横幅只影响本次展示；暂缓提醒会持久化，到所选日期恢复。应用关闭、电脑休眠时不执行检查，当前不使用系统通知或后台常驻服务。

可以从提醒事项或其他未结任务记录跟进、填写下一次日期、查看跟进历史及复制催办草稿。跟进记录与任务实际进展分开保存；记录一次沟通不代表对方已经交付，也不自动解除依赖。草稿不会自动发送到飞书。

## 项目问答

“项目问答”是本机用户入口，可选择单个或全部项目。常用问题包括“今天先催谁”“哪里有阻塞”“本周项目状态”“有哪些里程碑”，也可以输入任务名称查找当前记录。

默认本地规则回答，无需模型密钥。回答联合当前任务及最近进展、有效依赖和阻塞、已确认安排、项目目标与里程碑、已确认记忆和日报摘要，附更新时间和依据。任务依据可打开任务，记忆原文可回到资料核对。日报明确作为生成时的历史快照使用。

勾选模型回答后，只有可用且已授权访问资料的模型才会收到本次问题与筛选记录。未配置或未授权时保留本地回答。模型请求在数据库线程外运行；引用必须来自发送集合。回答过程中相关记录、模型配置或工作区还原发生变化时，拒绝展示过期答案，需要重新提问。

检索和模型上下文有条数与长度上限，界面显示相应限制；大型工作区可以缩小项目范围或使用任务名称查询。引用有效不保证模型的语义判断完全正确，关键决策仍应核对原文。飞书预览和群代答复用此问答范围，但必须限定为绑定的单个项目，并在发送前再次核对项目记录和模型设置。负责人或截止日期缺失明确标为未知；两个字段中只有一个有值时保留已知并标为部分回答。

## 数据与恢复

SQLite schema 6 新增项目档案、里程碑及任务关联、跟进状态和跟进记录。升级在事务中执行；旧版备份在私有暂存副本中迁移，再校验日期、版本和项目关联后恢复。新数据与原工作区一起备份，模型及飞书凭据继续独立保存。

总览、跟进和问答中的检查日期用于评估当前记录。原有每日清单与日报的历史快照规则保持不变，不应把总览中的旧检查日期视为完整的历史项目快照。

## 验证入口

`cargo test -p project-assistant-core --locked` 覆盖提醒日期边界、版本冲突、跨项目隔离、里程碑完成与重开、旧工作区迁移、重启与备份还原，以及统一问答的本地意图、引用校验和迟到答案拒绝。

`npm run build`、`cargo fmt --all --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings` 检查前端、格式和 Rust 工作区。原有四组真实进程验证继续使用 `verify:restart`、`verify:ai`、`verify:workflow`、`verify:planning`。

界面验收使用隔离工作区和真实 Rust 核心，已操作保存项目目标、新建关联任务的里程碑、记录跟进、设置次日暂缓、查询延期依据及从回答打开任务。模型测试使用本机 HTTP 夹具，不代表真实账号或模型质量验收。

本次验证：125 项 Rust 测试、工作区 Clippy 与格式检查、前端生产构建通过；restart、ai、workflow、planning 四组真实进程回归通过。大样本测试另覆盖先匹配后限额、单项目旧任务查询、项目隔离以及当天排期不被未来计划挤出。
