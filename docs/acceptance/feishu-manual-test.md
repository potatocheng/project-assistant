# 新手可以照着做的项目助理验收

使用虚构项目“客服平台新手验收-A”。日期以2026-10-29北京时间为基准；以后使用时整体平移日期。数据在同目录的 [feishu-seed-data.txt](feishu-seed-data.txt)。

先检查一个完整小流程，再增加功能。不要一开始把全部剧情粘进去，否则很难验证“承诺还未完成”“旧信息被更正”等中间状态。

## 1. 先用桌面版跑通，不需要飞书

1. 打开最新版 `target/debug/project-assistant-desktop.exe`，创建项目“客服平台新手验收-A”。
2. 进入“资料 → 导入资料 → 粘贴文本”，只复制数据文件的**第一批**正文，填写对应标题，导入。
3. 想验证AI整理时，在“全部功能与设置 → 模型设置”保存可用模型并测试连接。远程模型需在界面允许发送这套虚构资料。导入后在资料上启动提取，核对待确认内容及原文，再确认任务候选。
4. 如果暂时不配置模型，直接手动建下方三个任务。术语解释、卡点引导、跟进结果记录、排期、汇报等本地能力仍可测试；这一轮不验证AI提取。

| 任务名 | 负责人 | 截止日期 | 状态、进度 | 建议执行方式 |
| --- | --- | --- | --- | --- |
| 登录接口联调 | 小周 | 2026-10-30 | 阻塞，20% | 跟进交付 |
| 验收标准确认 | 李娜 | 2026-10-29 | 待办，0% | 跟进交付 |
| 准备UAT环境 | 阿杰 | 2026-10-28 | 未完成，0% | 跟进交付 |

任务发生日期填今天；截止日期可以是过去的原定日期。AI候选的状态、人员和日期需要核对。“亲自执行”只用于由你亲手完成的任务；产品不会仅凭姓名自动认定哪位是你。跟进他人的任务主要在“需要我介入”、任务页及提醒页查看，无需强求全部进入“我的今日工作”。

## 2. 先验收这次新增的三个功能

从任务详情进入即可。若首页已展示该事项，也可点旁边的“帮我推进”。

| 编号 | 你做什么 | 应该看到什么 | 结果 |
| --- | --- | --- | --- |
| N01 | 打开“登录接口联调”，点击“接口”“联调”，再点“不懂的词”里的“验收标准” | 白话解释、通用例子和一个下一步行动；不要求配置模型 | 待测试 |
| N02 | 解释窗口按Esc，再按Tab操作 | 只关闭最上层窗口，回到之前操作的位置；按钮可用键盘访问 | 待测试 |
| N03 | 点“帮我推进 → 等别人回复” | 建议确认具体结果、答复时间和协调需求；未答复原因仍待核实 | 待测试 |
| N04 | 依次选择其余四种卡点 | 建议和草稿跟随选择变化；“我也不确定”先问“现在等谁给出什么结果？” | 待测试 |
| N05 | 修改沟通草稿，复制到记事本核对 | 复制的是修改后的草稿；你可自行决定何时发到测试群 | 待测试 |
| N06 | 写一半跟进结果，关闭，再打开或重启产品 | 恢复未保存的本机草稿，不自动变成正式记录 | 待测试 |
| N07 | 输入“记录1”，选“先记下情况”，下次跟进明天，保存 | 新增记录及下次日期；任务仍阻塞、20%，截止日期仍2026-10-30 | 待测试 |
| N08 | 输入“记录2”，选“有了实际进展”，保存 | 状态变为进行中；进度百分比保留原值，可在“更新进度”明确填60% | 待测试 |
| N09 | 输入“记录3”，选“已交付并确认完成”，核对提示后保存 | 任务完成、100%，后续跟进结束；其他任务和整个项目仍需检查 | 待测试 |
| N10 | 保存后重启，查看任务和跟进历史 | 记录、原日期和状态保留，重复打开页面不会重复创建记录 | 待测试 |

“明天再看”安排的明天提醒不能要求今天弹出。想立即验证，可对未完成任务将下次跟进日设为今天；应用保持运行，在提醒页刷新检查。系统通知还取决于桌面通知设置。

## 3. 再把同一套数据放到飞书

1. 建一个独立测试群、一份新版飞书文档，名称均带“客服平台新手验收-A｜测试”。文档只放第一批正文，后续消息按批新增发送。普通文字和新版文档适合这轮验证。
2. 应用中打开“全部功能与设置 → 飞书个人助理”，输入企业自建应用的App ID、App Secret，按界面完成权限申请与个人授权。如果你没有这些凭据，需要企业中能创建或管理飞书应用的人协助这一步。
3. **采集开关和自动回复开关分别设置。** 初次先保持“用我的账号自动回复”关闭，完成读取和核对。
4. 打开“记忆中心 → 飞书资料”，添加群ID和文档链接，明确选择保存到本地项目A，启用同步并保存，然后“立即同步”。
5. 在资料列表检查是否已有群消息和文档原文，打开原文核对正文、来源。读取失败先看每个来源的错误原因。
6. 在“模型设置”配置好模型及资料授权；在“记忆中心 → 空闲整理”开启整理。为了便于观察，初轮关闭“自动记住飞书资料中的独立新事实”，再保存。
7. 可以点“立即整理一项”。它只安排一项工作，不代表全部资料完成；看整理记录和剩余队列，必要时继续。也可停止操作，等待空闲整理，默认空闲120秒开始。
8. 打开待确认和资料页核对记忆、任务候选，确认后再检查任务、项目问答和首页。

群读取不需要@任何人。可以由你一个账号发送数据，正文已经明确写了模拟负责人。真实飞书权限、网络、模型和消息索引需要在你的环境验证；原文采集成功与模型整理成功要分别记录。

## 4. 飞书分批验收顺序

每批都按“新增发送 → 立即同步 → 检查原文 → 整理 → 核对候选/更正 → 确认 → 检查任务/问答”的顺序走。不要为了催同步一直编辑同一条旧群消息；请新增一条明确的更正消息。

| 编号 | 输入批次与操作 | 期望与检查方法 | 结果 |
| --- | --- | --- | --- |
| F01 | 第一批文档同步整理 | 原文完整可打开；人员、日期、否定条件可追溯，任务候选核对后再确认 | 待测试 |
| F02 | 再点一次同步，文档不做修改 | 没有新增远程内容时不重复堆积相同资料或正式任务 | 待测试 |
| F03 | 发送第二批消息1 | 可以找到承诺；“承诺交付”保持为未实际完成，任务不能由此成为100% | 待测试 |
| F04 | 发送第二批消息2并提问“单点登录已经批准了吗” | 回答尚未批准、需王经理决定，有依据；不把申请写成批准 | 待测试 |
| F05 | 发送第二批消息3，使用卡点引导 | 保留未回复现象及原因未知；不认定人员不配合或项目已经延期 | 待测试 |
| F06 | 发送第三批更正 | 更正需核对，旧原文和历史保留；不能悄悄覆盖旧结论。待确认冲突可能暂不参与当前问答 | 待测试 |
| F07 | 核对并采用第三批更正，检查结构化任务 | 当前负责人为小林，约定日期2026-10-31。若产生任务更新候选，关联原任务后核对确认；只有记忆更新时，需核对任务并明确更新，不能假定两者已同步 | 待测试 |
| F08 | 发送第四批，核对任务更新或用结果表单记录 | 可以表示有实际进展、正在联调；60%需在候选或更新进度时明确确认，不能把它当作完成 | 待测试 |
| F09 | 发送第五批并核对更新 | 登录接口联调可以明确确认完成；准备UAT环境和整个项目不会一起被视为完成 | 待测试 |
| F10 | 问“这个项目预算是多少” | 明确未记录/未知，不编造金额 | 待测试 |
| F11 | 问“项目实际上线已经延期了吗” | 给出当前依据与缺项；逾期任务或潜在风险本身不等于已确认上线延期 | 待测试 |
| F12 | 新建项目B，只给B绑定独立来源，导入B数据 | 同名“登录接口联调”：A为小周/10月30日，B为小吴/11月5日，回答与引用遵守所选项目 | 待测试 |
| F13 | 反复同步已处理批次，再重启产品 | 任务不无故重复，来源及更正历史可回看；应用重新运行后继续按设置工作 | 待测试 |

AI候选的条数和措辞不要求完全一致。按负责人、日期、状态、范围、否定和条件是否正确判断；缺提、错误、证据不足均要记录，不能只看“整理成功”。

可以用下面的标准答案核对问答，先选择正确项目，并完成对应批次的人工核对：

| 问题 | 第一批确认后 | 后续批次确认后 |
| --- | --- | --- |
| 登录接口联调由谁负责，截止日期？ | 小周，2026-10-30 | 保留这两个字段，承诺不会自动改原定截止日 |
| 准备UAT环境由谁负责，何时完成？ | 阿杰，原定2026-10-28，已过期且尚无新日期 | 第三批更正确认后为小林，新的约定日期2026-10-31；任务字段另行核对 |
| 单点登录已批准了吗？ | 尚未批准加入一期，需王经理决定 | 第二批只是提出需求，仍未批准 |
| 测试账号已开通了吗？ | 尚未确认开通 | 第四批说明2026-10-29已开通，未提供具体几点几分 |
| 项目预算是多少？ | 未记录，不能确定 | 所有批次都没有预算，仍不能确定 |
| 项目实际上线延期了吗？ | 只记录潜在风险与逾期事项，尚无已确认的上线延期 | 不能从上述剧情自行推断已批准延期 |
| 登录接口联调已完成了吗？ | 尚未完成，20%，阻塞 | 第二批承诺仍未完成；第四批60%、进行中；第五批交付检查通过后才可以明确确认完成 |
| 项目整体完成了吗？ | 没有 | 第五批只完成一个任务，其他任务、里程碑与正式验收分别核对 |

回答有引用时，请点开核对是不是同一项目、同一事项和适用的新版本；只有引用数量正确还不够。

## 5. 自动代答单独测试

先使用“飞书个人助理 → 回答预览”，确认绑定项目和答案范围，再启用测试群的个人账号自动回复。飞书资料订阅里的项目绑定用于采集；代答还需要在飞书个人助理里配置群与项目绑定。

| 编号 | 你做什么 | 正常表现 | 结果 |
| --- | --- | --- | --- |
| R01 | 启用后，请另一位真实群成员@已授权的个人账号，问负责人和截止日期 | 回复依据来自绑定项目；用授权个人账号回复，附可核对来源 | 待测试 |
| R02 | 再次检查同一条问题消息 | 同一条消息最多回复一次；不是每次检查都重复发送 | 待测试 |
| R03 | 用自己的已授权账号发送问题，或发普通未@消息 | 不触发自己的自动代答；这不是故障 | 待测试 |
| R04 | 从另一个未绑定的测试群发提问 | 不使用项目A的数据自动回复该群 | 待测试 |
| R05 | 另一成员问未记录的预算 | 不编造预算；全无依据时可能跳过发送，可在最近记录看处理结果 | 待测试 |

首次启用只处理启用后的新@消息。检查前先确认桌面应用仍运行；存在轮询与飞书索引延迟，没立即回复先看“最近处理记录”和错误，不能仅按等待秒数判定故障。

## 7. 怎样记录结果

把每个“待测试”改为“通过 / 失败 / 待确认 / 环境未就绪”。未配置飞书或模型时使用“环境未就绪”，不能当成产品通过。

发现问题时，每次记一项：

```text
编号：例如F07
测试时间：
软件版本/程序路径：
所选本地项目、飞书来源：
使用第几批、哪条消息：
操作步骤：
我期待看到：
实际看到：
相关截图或原文依据：
能否重复出现：
```

推荐先跑N01–N10与F01–F11，再做项目隔离、代答和其他管理功能。全部核心流程通过说明这些场景正常，不代表所有权限组合、真实业务措辞和极端情况都已覆盖。
