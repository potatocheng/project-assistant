# 账页 Ledger · 界面设计语言

账页把项目资料、确认后的记忆和每天要做的工作，放在同一个安静、可查证的工作区中。纸色承载内容，墨色建立层级，靛蓝指向操作；颜色不替代事实和状态说明。

这份文档记录已确认的设计方向及后续页面应遵循的约定。验收要求是检查清单，实际通过情况以当次构建与浏览器记录为准。

## 1. 页面先回答什么

一个页面先回答一个主要问题，再提供相关操作和证据。

| 层级 | 内容 | 呈现方式 |
| --- | --- | --- |
| 定位 | 当前页面、项目和日期范围 | 清晰的页面标题，附近放范围选择 |
| 主要工作 | 今天最需要处理的事项、正在查看的任务或原文 | 连续列表、阅读区或工作面，占据主要空间 |
| 操作 | 当前工作的下一步 | 一个最突出的主操作，相关操作使用次级按钮 |
| 背景 | 来源、历史、详细设置 | 详情区、折叠内容或对话框，按需展开 |

不为每个数字建立独立卡片。普通内容使用留白、标题和细分隔线组织；只有可独立操作的项目、需要保持上下文的详情或明确分组才使用容器。不要添加装饰渐变、宣传式大标题和重复提醒。

## 2. 统一导航与工作区

所有业务页面共用左侧分组导航。分组标题降低视觉重量，当前页面通过背景、字重和 `aria-current="page"` 共同标识。

| 分组 | 页面 |
| --- | --- |
| 今天 | 今日概览、待处理行动、提醒与跟进、待确认内容 |
| 工作 | 每日清单、全部任务、工作日报 |
| 沟通 | 项目问答、聊天回复 |
| 项目 | 项目总览、风险与决策、变更与验收、周报与会议 |
| 资料 | 项目资料、项目记忆 |

工作区搜索靠近导航顶部，设置和低频数据工具放在底部的“工具与设置”。数量提示使用简短数字；需要行动的数量可以使用提醒色，不让所有入口同时高亮。

桌面保持导航可见，导航自身可以滚动。页面在右侧独立承载工作。资料与记忆的项目选择、查找和记录列表属于页面内的目录栏，不再兼任全局导航。目录、原文和证据之间应保持明确的从属关系。

窗口变窄后，主导航改为抽屉；顶部显示当前页面名称和导航入口。不要把桌面所有栏位缩小塞进同一行：目录与详情按可用空间重排，保留可读文字和明确的返回路径。长资料名、长任务名和来源定位应折行或有完整内容的查看方式，不能撑宽页面。

## 3. 颜色与主题

`src/design/tokens.css` 是主题颜色、字号、圆角和时长的共同来源。组件使用语义变量，不另建页面配色，也不在深色主题外再写白色背景。

| 作用 | 变量 | 使用规则 |
| --- | --- | --- |
| 工作区背景 | `--bg-canvas` | 承载侧栏与页面外围的纸色底 |
| 内容表面 | `--bg-surface` | 阅读、表单和主要内容区域 |
| 次级表面 | `--bg-subtle`、`--bg-muted` | 详情背景、悬停与轻量分组 |
| 强调底色 | `--bg-emphasis` | 需要更明确区分的中性区域 |
| 正文 | `--text` | 标题、正文和重要数据 |
| 辅助文字 | `--text-secondary`、`--text-muted` | 说明、时间、范围与来源信息 |
| 最弱文字 | `--text-faint` | 装饰性、非必读内容，不能承担关键状态 |
| 边界 | `--border-subtle`、`--border`、`--border-strong` | 从区域分隔到控件边界递增使用 |
| 主操作 | `--accent`、`--accent-hover`、`--on-accent` | 靛蓝主按钮与其文字 |
| 选中与链接 | `--accent-soft`、`--accent-text`、`--accent-border` | 导航选中、正在进行、可点击内容 |
| 已完成或已确认 | `--success*` | 明确的成功结果和确认状态 |
| 等待、阻塞或待核对 | `--warning*` | 需要关注但尚未失败的状态 |
| 失败或高风险 | `--danger*` | 错误、失败、破坏性操作 |
| AI 来源 | `--ai*` | AI 生成标记与相关说明，不表示已确认 |

带 `-soft` 的变量用作底色，带 `-text` 的变量用作该状态的文字，带 `-border` 的变量用作边界；不要直接把亮色状态值铺满整个工作面。颜色始终和文字或图标一起表达含义。

默认跟随 `prefers-color-scheme`。根元素的 `data-theme="light"`、`data-theme="dark"` 用于显式主题覆盖和验收；未设置时保持系统跟随。深色模式通过替换同一组语义变量实现，不能整页反色。对话框、弹出工具、禁用控件、选中行和空状态都属于主题范围。

## 4. 内容来源与可信程度

来源和确认状态是两条独立信息，不能用同一个颜色标签混为一谈。

| 内容 | 视觉与文字约定 | 仍需保留的信息 |
| --- | --- | --- |
| 已确认 | 文字明确写“已确认”，需要时使用成功色 | 当前版本、确认记录、来源证据 |
| 待确认 | 标记“待确认”并提供核对操作，使用提醒色 | 候选内容、原文、确认或拒绝入口 |
| AI 生成 | 用 AI 色系标记“AI 生成”或生成来源 | 依据与人工确认状态；生成不等于确认 |
| 原文 | 中性阅读表面，引用使用细边界和来源定位 | 资料名、段落或时间定位、原文内容 |

一条由 AI 提取后经人工确认的记忆，可以同时保留 AI 来源与“已确认”。不能因为有引用就把候选视为事实，也不能因为改了任务阶段就显示为交付完成。历史日报继续作为版本快照展示。

界面导航、任务和表单使用系统无衬线字体；较长的原文或引用可以使用 `--font-serif`，并保持足够行高。技术标识等少量定宽内容可使用 `--font-mono`，避免把第三种字体扩散到普通界面。

## 5. 字体、间距和边界

正文基准为 `--fs-md`（14px）；13px 适合列表辅助信息，12px 只用于时间、计数和短标签。正文不能通过不断缩字号来适应窄屏。页面标题使用 22px 或 28px，区块标题通常为 16px 或 18px；同一层级保持一致。

文字行高按用途选择：标题使用 `--lh-tight`，普通界面使用 `--lh-normal`，长说明和原文使用 `--lh-relaxed` 或阅读区更宽松的行距。长中文段落控制行宽，阅读区参考 `--reading-max`（760px），常规页面参考 `--page-max`（1080px）；复杂任务工作区可以按实际信息结构扩展。

间距以 4px 为基础，优先使用 `--space-*`。控件内部较紧，条目之间清楚，区块之间留出明显距离。圆角以 4–8px 为主，12–16px 留给较大的弹出层或独立工作区；不把所有按钮和状态做成胶囊。阴影用于浮层和层级变化，普通列表不依靠投影区分。

## 6. 常用组件约定

- **按钮**：一组相关操作有明确主次。主按钮使用靛蓝；次级按钮使用内容表面和边界；文字按钮处理补充操作。危险操作使用危险色并说明实际影响。处理中保留按钮原意，并呈现忙碌状态。
- **表单**：字段有可见标签，提示和错误靠近字段。占位符不代替标签。输入、选择和文本区共用边界、圆角和焦点状态；勾选控件不套用普通文本框尺寸。
- **列表和表格**：先突出任务或资料名称，再呈现状态、时间与负责人。行选中和行悬停可区分。整行点击不能遮挡行内的独立按钮。
- **详情与证据**：主要内容先出现，来源与历史随后。可展开原文，不用长篇提示反复解释整个系统。切换选择时更新详情，保留合理的滚动和焦点。
- **通知**：只提示当前需要处理的事项，并能定位到相应页面。恢复提示、业务提醒、错误反馈分别表达，不用多个高饱和横幅争夺注意力。
- **空状态与加载**：空状态解释缺少什么并提供下一步；错误提供重试或恢复入口。加载保持主要页面结构，避免整个工作区闪烁。进度和处理结果应对辅助技术可感知。
- **对话框**：有标题、关闭入口和清晰操作顺序。内容过长时内部滚动，底部操作仍可到达。嵌套对话框只由最上层响应关闭和焦点循环。

## 7. 交互与可访问性

动效帮助用户识别切换，不作为装饰。颜色与悬停反馈使用 `--dur-fast`；导航抽屉和详情出现使用 `--dur-base` 或 `--dur-slow`，缓动使用 `--ease-out`。不要在每个数据条目上重复播放入场动画。

当 `prefers-reduced-motion: reduce` 生效时，去掉空间位移和非必要过渡；保留必要的处理中提示。用户应该不依赖动画也能理解结果。

键盘可以到达所有操作，焦点必须清晰可见。图标按钮提供动作名称；当前页面、展开状态和模态语义使用对应的 ARIA 属性。抽屉与对话框打开时将焦点送入，关闭时送回触发入口；背景不可交互，焦点循环在当前浮层内。`Escape` 关闭可关闭的最上层浮层，提交中的操作遵循其忙碌约束。

桌面紧凑控件参考 `--control-h`（34px）；触屏操作区域应更宽裕，常用入口以约 44px 的可点击区域为目标。普通小字与背景的对比度以 4.5:1 为目标，控件边界、焦点和重要图形以 3:1 为目标；需要在两个主题分别核对。不要只看色值名称就推定可读。

## 8. 维护与验收

新增或重构页面时先确定主要工作、范围选择、主操作和证据位置，再复用上述变量与组件。新增颜色必须先说明其语义并进入主题变量；不要新增整套页面级 `:root` 配色或叠加旧主题覆盖层。兼容旧类名时应集中处理，避免形成第三套视觉系统。

每次界面变更按影响范围检查以下内容，不以文档存在或构建成功代替视觉验收：

1. 运行 `npm run typecheck`、`npm run build` 和 `git diff --check`。
2. 用隔离演示工作区检查有数据、空状态、加载、错误及长文本；不要为了视觉验收修改真实业务数据。
3. 检查今日概览、任务与每日清单、项目管理、资料原文与记忆、问答或聊天记录、设置与备份等代表页面。
4. 在桌面与窄屏分别检查导航、目录、详情、长对话框及工具菜单；确认页面不横向溢出，所有入口仍可到达。
5. 核对系统浅色、系统深色以及显式主题覆盖；检查文字、状态、选中、表单和浮层。
6. 用键盘检查打开、焦点循环、`Escape` 和关闭后焦点恢复；检查减少动态效果设置。
7. 查看浏览器控制台和网络错误，记录实际截图、窗口尺寸、验收路径与仍未覆盖的部分。
