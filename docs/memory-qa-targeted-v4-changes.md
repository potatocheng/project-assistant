# 最后一次开发修复：限定关系与顺序检索

第三次真实20题已完整保存，质量门槛未过；其结果、评分、失败gate和费用不改写。本次是事前登记的第4次、也是最后一次允许的fresh20，递归扣除前三次729请求/3,346,785 tokens，剩471请求/2,653,215 tokens。全部评分、gold、门槛及18项评测文件保持原样。

## 修复依据

- 第三次顺序机制题实际producer未含本系统的按序编码、上下文初始化事实；review把必要的时序未知标为unasked并判完整，未触发补查。旧提示中“按序组合可回答机制”过于宽泛。
- 单体模型的引用中实际已有基础模型、predicate-specific、Primary/Secondary正文，部分自动retrieval理由却称缺失。保留原分和原理由，不能用评分分歧伪造漏检或改gold。另一方面，整体组成句也可能显式提到被问单元，整段投影删除会损失称谓之间的关系导航。
- 变数量机制的原问可能属于Mechanism，而必要缺项被Count分类压住；padding/batching/内部维度等未问细节应继续与核心变数量关系区分。

## 生产修改

1. 首次QA检索增加很小的问句语言导航：明确问顺序机制时，把sequential/sequentially/chronological或中文时序词导航为`sequence order`。原问题、项目、日期保持原样；显式提供的检索计划（含空数组和非法值）不被覆盖。否定或非机制问句不触发。只在QA入口构造检索参数，冻结的search、memory_query和提取实现保持不变；导航不支持事实、不推断任何编码器或模型架构，也不增加模型调用。
2. 提示须核对原问的明确限定关系，不能仅据通用组件、位置分工或输出拼接判定顺序机制已完整。
3. 必要关系未知项被provider误判unasked时，保留原始provider对象；本地守卫只降有效完整性，记录原因。未问批处理、维度等不因此一律保留，不清除任何必要未知项来获得分数。
4. 目标投影保留同时显式含被问单元的整体关系正文；保留整条及条件，不把整体的组成冒充单体的组成。
5. 核心变数量机制缺项可继续导航；纯未问实现细节仍不补查。

模型调用5次、24条/36k字符、最多一次额外生成等上限不变。源码、二进制及11命令确定性验收完成后冻结；第4次真实20题全门槛通过才运行完整100题。若未通过，如实保留失败结果，不自动增加开发次数、预算或降低门槛。
