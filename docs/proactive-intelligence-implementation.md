# 主动智能首批实施说明

日期：2026年11月3日。对应[升级方案](proactive-intelligence-plan.md)的 P0 与 P1 首批本地能力，工作区 schema 14。

## 如何使用

打开“待处理行动”，默认进入“持续推进”；原有规则巡检保留在“巡检提醒”。持续推进根据现有任务和资料自动准备三类事项：

| 场景 | 自动准备 | 明确选择后执行 | 后续核实 |
| --- | --- | --- | --- |
| 任务逾期或期限晚于关联里程碑 | 当前期限、任务状态、相关里程碑及处理选项 | 记录实际跟进，或调整任务截止日期并保存理由 | 按约定时间继续检查，不把新承诺当成交付完成 |
| 约定跟进日到达 | 待核实任务与跟进日期 | 保存实际跟进记录和下次复查时间 | 未完成时保持持续责任，到期重新准备处理选项 |
| 资料需要核对 | 待审内容、当前记忆和原审核入口 | 转入已有资料审核，或约定稍后核对 | 原审核实际处理后再更新事项状态 |

每个事项可单独暂停或恢复；全局开关在按项目查看时仍作用于整个工作区。过程记录在页面底部查看。应用退出或电脑休眠时不运行，下一次启动继续检查；恢复备份后需要重新启用。

目前“持续推进”与原“巡检提醒”分别保存开关、忽略和暂缓状态；两者的抑制规则尚未合并。需要停止新流程时，请在“持续推进”中暂停相应事项或关闭自动整理。新流程不新增系统推送。

“今日重点 / 帮我推进”的模型分析现在对展示的标题、判断、行动、问题和沟通草稿逐句复核。引用存在但含义不支持、遗漏必要未知、核验失败或分析期间资料变化，均停止展示该模型结果。保留原本不调用模型的本地功能。

## 实施机制

业务写入通过 SQLite 触发器在同一事务内保存待处理实体；重复事件合并，处理时读取最新记录。本地调度每次最多处理 64 个实体、登记 32 个到期事项。事件、事项、运行、选择与历史持久化；决策与任务/跟进变更在一个事务完成。新的选择同时校验事项版本和当前依据；相同决定 ID 重试只返回原结果。

方案参数由现有业务接口校验。模型不能生成任意命令再执行；本次本地持续推进没有网络工具或模型调用。任务调整复用任务历史和跟进接口，资料冲突继续使用原审核接口。项目暂停、归档和停止推进会撤下相应行动资格。

模型建议每轮最多一次生成、一次语义核验，共享既有上下文、输出和总超时预算。核验使用程序生成的句子 ID 和引用白名单，分别保存事实、假设、建议和未知的检查结果。成功、失败和重启中断均保留运行记录；缓存命中显示原分析成本，不新增请求。在持续推进页面展开“模型分析记录”可查看当前范围的请求计数和最近记录；该记录独立加载，不影响本地事项处理。

建议分析请求限制为每天全局 100 次、每项目 60 次，同时最多三个分析；生成与核验分别计一次。失败、在途和未报告 usage 的请求占用额度，恢复旧备份不会返还已预留额度。提供方未报告 tokens 时保留未知，不显示为零成本。这是请求数量上限及已报告 token 统计，不是所有模型入口的统一费用上限。

## 本次范围与后续工作

首批借鉴了 DeepSeek Super-agent 的事项状态、事件续跑、按需读证据与前台决策分工。当前采用单个数据库 actor 上的短事务规则流程；没有引入通用多模型 Worker 或长时间网络步骤租约。

尚待后续实施：聊天消息与事项的语义关联、主动模型研判、飞书决策卡片及回调、外部动作回执、跨事项授权策略、统一全产品预算、历史日志保留策略、全天在线服务。已有飞书同步和个人代答按原功能运行，未新增主动外发。

同模型语义复核仍可能共同犯错。本轮合成与 mock 测试验证程序约束和恢复机制，不代表真实中文项目行动准确率；业务收益需用人工标注的实际案例另行验收。
