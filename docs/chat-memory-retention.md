# 聊天记忆分层与上下文（v9）

提取提示版本为 `project-memory-task-extraction-v9-conversation-retention`，数据库 schema 11。保留既有不可变原文、逐条证据、人工修订优先、任务预算和检查点恢复机制。

## 上下文

飞书正文保存 thread/root/parent 关系。同一读取批次中有显式回复或话题关系的消息归入同一讨论，跨越原 10 分钟分桶；无关系消息沿用时间桶。同步完成搜索后按需补读缺失的父消息和根消息，最多四层、200 个关联 ID，每次批读最多 50 个；只接受指定群的返回，不推进失败请求的游标。未能读到的父消息不合成原文。

纯文本解析仍逐行保留原始 segment ID。阅读计划根据消息关系补入父消息、直接回复及元信息；明确回复中的条件与其所指事实一并检查，缺父消息或缺条件的候选进入审核。扩展中英文指代、条件和列表引导语的诊断规则。

这是有预算的显式关系阅读：不遍历整个群史，不保证跨话题、没有引用关系的远距离指代完整；大讨论仍受已有输入和复查预算限制。没有把已有来源与历史记忆重新关联或自动重写。旧消息撤回与旧编辑的既有同步边界仍存在。

## 保留策略

提取同时接收项目名称、描述、目标、状态和目标日期的有限背景，用于判断相关性，不能作为候选证据。背景在提取任务首次启动时冻结，恢复使用同一份背景；重新提取的新任务才读取新背景。该背景保存在项目备份中。

模型每条输出 `retention.layer` 与理由：

| 层次 | 候选处理 | 正式记录的使用 |
| --- | --- | --- |
| durable 长期记忆 | 原有证据审核；采集来源可依设置自动接受独立新事实 | 默认问答可用 |
| working 工作状态 | 待用户确认，不自动接受 | 默认确认后 7 天复核，可在候选编辑及记忆修订中改日期；复核日及以后退出默认问答 |
| clarify 待澄清 | 保存审核草稿，无可确认提案 | 人工澄清后选择长期或工作状态才能生成提案 |
| archive 仅存原文 | 留存可重新审核的草稿，无可确认提案 | 原文可人工查看，不自动形成正式记忆 |

新的模型响应缺少保留方式时转为待澄清。旧检查点和人工记录兼容原有长期保留方式。复核日期是应用策略，不是推断出来的事实失效时间；到期不删除资料。用户可以通过修订更新日期、转长期记忆，或将已结束的状态转为仅存原文。策略随修订保存；合并依据保留目标策略和原复核日期，不借此自动延长状态。

问答的正式记忆、目录和原文补充路径均应用当前修订的保留策略。某来源关联的工作记忆到期后，该来源的原文也不重新进入回答以绕过复核。原文补充仍受原有来源级保守限制，并未新增无记忆锚点的全库原文检索。

## 去重与更新

同一来源、内容、类型、主体、角色、条件、有效期及保留层次一致的提案，不再因导航 topic 措辞或证据片段不同而重复生成。补充引文同步更新证据索引；原始草稿分别保留。人工编辑或审核过的候选沿用保护规则。不同真实范围、层次不自动合并。

比较前在当前项目的记忆中做全文精确匹配优先与 BM25 相关性排序，避免较早的相关事实被无关近况挤出。比较包含组织范围与保留策略，自动合并要求范围及层次一致。比较理由须说明替代、取消、完成或补充关系；人工确认的替代仍使用同一记忆的新修订，保留历史。

比较输入继续限制在 32,000 字节。未覆盖全部当前记忆时，不把局部召回冒充全库完整，新内容仍保守进入待确认。该优化改善相关记录可见性，不保证消除大项目的审核队列。

## 验证

针对性回归覆盖四层草稿与确认状态、复核日期、原文绕过限制、不同 topic 去重、适用范围隔离、较早相关记忆召回、跨时间回复关系、不同指代和缺失父消息。完整测试、构建与恢复验证结果见本次交付说明。

真实业务质量采用人工完整事实清单，不只标注系统已输出的内容。复制 `chat-retention-annotations-template.json`，按完整脱敏话题填写期望层次、实际层次、依据是否正确、条件是否完整及是否错误替代。漏掉的事实也要加入，`observedLayer` 为 `missing`。只有完整清单且全部标注后才设置 `inventoryComplete: true`。

运行 `node scripts/score-chat-retention.mjs annotations.json scores.json` 得到层次混淆、必要信息召回、无用信息保留、语义审核结果和每千条消息成本。未标注的指标为 null。当前未提供真实业务人工标签，因此本轮回归不能证明真实聊天准确率或成本收益。
