本设计依据已完成的QASPER真实模型评测，解决提取截断、组织字段导致整条拒收、成功批次无法恢复的问题。第一阶段交付可恢复的候选提取链路，再以同题回归测量最终回答的变化。

## 数据流与确认边界

```text
原始资料及版本
  → 带来源定位的批次计划
  → 一次模型提取事实与可选组织字段
  → 分级校验
  → 批次草稿持久化
  → 待确认候选或组织待审核草稿
  → 用户确认
  → 正式记忆及当前修订
  → 检索与回答
```

事实正文、来源证据、导航标签和适用范围分别保存。两个逻辑阶段不要求每条事实额外调用一次模型；只有需要修复或核验的项目才消耗额外预算。原文和模型原始输出可追溯，草稿不进入正式记忆检索。

## 一 提取预算

2400字符和6144输出token作为开发试点初值，由实际usage校准，不能直接视为最优参数。

- 估算完整请求的token，包含系统提示词、schema、资料和重叠上下文；保留字符上限兜底，不将中英文字符数当成相同token数。
- 按段落和句子切分，保留否定、限定条件与必要的前文。长段落才使用重叠窗口，来源ID保持稳定。
- schema与Rust运行时使用同一份限制：正文长度、每条引文数、引文长度、记忆数、任务数和响应总大小。不能只在提示词中声明上限。
- 控制每条候选与整份响应的实际输出预算，避免所有字段同时达到schema上限时远超输出容量。达到数量上限时记录覆盖状态，必要时细分批次，不能默默把“最多12条”当作已完整提取。
- 明确区分输出截断、数量越界、协议错误、内容过滤、网络、鉴权和限流错误。仅对可归因于容量的错误有界拆分；过滤、鉴权及限流不触发拆分重放。
- 同时限制任务的总请求次数、累计输入输出token、拆分深度和总耗时。截断父请求也计入消耗，不能只统计成功叶批次。

## 二 分级校验与审核

| 对象 | 处理方式 | 对正式记忆的影响 |
|---|---|---|
| 空正文、非法来源、无效引文 | 拒绝候选，记录具体原因 | 不可确认 |
| topic等导航标签不合法 | 保存原值和原因，隔离该标签 | 正文和其他字段通过后可进入待确认候选 |
| entity、role、conditions、validity不合法或矛盾 | 保存正文和证据为组织待审核草稿 | 完成审核前不可作为无范围事实确认 |
| 主体、否定、数值、时间与引文语义关系可疑 | 标记事实支持待审核 | 引文逐字存在不能替代语义核验 |
| 全部校验通过 | 保存待确认候选 | 用户确认后才成为正式记忆 |

优先提取保留原文语言的原子事实；中文显示译文可以独立提供，不覆盖作为事实依据的正文。模型确实无法确定的字段可以明确为空，但不能把“已生成且校验失败”改成“未知”并直接入库。

组织字段绑定当前修订。修改正文后重新校验，不继承旧范围。主题和实体别名主要帮助召回与排序；只有明确且已确认的范围信息可用于硬过滤。

去重键包含事实正文及经过校验的主体、条件、角色和有效期。同正文但范围不同的候选不能采用先到者覆盖，应保留差异进入审核。

## 三 批次持久化与恢复

沿用现有jobs表示一次提取任务，新增批次状态和草稿存储，避免重复建设整套任务系统。

批次和草稿绑定资料哈希、片段定位、模型配置版本、提示词与schema版本、批次计划哈希。保存父子批次关系、完整或失败状态、实际usage、候选原值、字段问题和结果哈希。

执行规则：

1. 模型调用在数据库事务外执行。
2. 每个批次完成后，草稿、原因、usage和批次状态在一个短事务中落盘。
3. 父批次因容量拆分时标记已被子批次替代；不得将父子输出重复入库。
4. 后续批次失败不会删除此前草稿；任务显示已完成和失败范围，不冒充全文处理完成。
5. 同一快照下恢复尚未完成的工作，已完成批次不重复调用；失败请求能否再次提交由明确的恢复操作和剩余预算决定。
6. 已取消、资料已变化或备份恢复后的旧任务，沿用epoch/generation门禁，不能把旧草稿提交给新任务。
7. 草稿转为候选和候选转为正式记忆分别检查来源版本、审核状态和幂等键。部分成功的范围应在确认界面可见。

这部分同时需要备份迁移、任务状态和确认界面的回归，不能仅添加内存队列后声称支持断点恢复。

### 评分分开进行

- 提取留存评分器看原文、问题所需事实和正式记忆正文，不看实际检索或最终回答；引文不能冒充正文中已经保留的事实。
- 检索评分器看问题和实际送给生成模型的文本，不看最终答案；段落ID覆盖另列为来源指标。
- 回答评分器看问题、人工标准答案和最终输出，分别判断正确、完整、部分回答和拒答；无依据断言另对实际引用检查。

同模型在隔离上下文中评分仍属于自动估计。抽取约30个分层案例供独立人工或其他评估者复核；尚无独立复核时明确保留限制，不将另一提示词包装成独立验证。

### 验收和停止条件

必须满足：无效引文不被接受；范围字段错误不能靠清空而确认；草稿不进入正式检索；恢复不重复调用已完成批次或重复建记忆；跨项目引用和gold泄漏为零；既有确定性回归通过；请求与token预算可以追溯。

开发目标为最终提取任务完成率达到95%以上、未恢复的截断低于1%，同时改善正文语义留存和完整回答率。这些是待验证目标，不是已实现结果。候选增加本身不构成验收。

预算按离线、试点、全量分别设上限，并依据试点usage给出全量消耗估计。出现范围被错误扩大、跨项目引用、gold进入生产输入或预算耗尽时停止新调用；试点仍频繁截断或没有语义留存时先排查，不直接扩大全量。

最终报告逐题新增成功、退化、仍失败的数量，分别列开发集、固定回归和新论文结果；同时给出模型请求、token、耗时、待审核率和失败批次恢复情况。英文论文结果不直接代表中文业务、长期更新或冲突处理能力。
