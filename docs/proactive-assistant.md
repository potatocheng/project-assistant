# 主动行动

主动行动持续检查已记录的项目事项，把需要推进的工作整理成带依据、建议和跟进草稿的行动。你记录一次处理情况和下次复查时间，它会保留这件事的责任，重启后继续跟进。

当前覆盖任务逾期、临近截止、停滞和约定跟进日，任务阻塞及未完成的前置依赖，里程碑或项目目标日期异常，以及风险决策、变更审批和交付验收中的管理关注。判断来自现有记录，记录不足时仍需补充实际进展。

## 使用方式

1. 在任务和项目管理中记录真实状态、负责人、期限及进展。
2. 打开“主动行动”，查看按优先级整理的行动、关注原因和依据。可按项目查看。
3. 处理后选择“已跟进，待复查”，写明处理情况并约定下一次复查时间；需要等待时可暂缓。
4. 助理到期复查当前记录，保留复查历史。任务完成或关注条件解除后，行动自动收束；可忽略暂不处理的行动，并在需要时重新打开。

“立即巡检”用于主动重评当前范围。默认已启用巡检，可在设置中关闭或修改复查间隔；关闭后立即巡检也保持暂停。

## 自动运行

应用启动时扫描已有记录，相关业务变化后重新评估，并每分钟检查待复查事项。复查间隔默认 60 分钟，可设置为 5 分钟至 7 天；在行动上约定的下次时间用于该行动的复查。应用需要保持运行；退出期间的到期事项会在下次启动后处理。

同一目标反复命中会更新已有行动，保留处理说明和历史。持续跟进、暂缓、已收束和已忽略的状态保存到本地工作区。扫描和草稿均使用本地规则，无需模型密钥，也不发送项目资料。

持续跟进和暂缓必须填写说明，并约定未来一年以内的复查时间。忽略会持续尊重这一次关注，条件解除后自动收束；以后同一目标再次出现风险时可重新进入待处理。暂停或取消的项目停止主动跟进，恢复项目后再判断。

主动行动提供判断和准备工作。任务完成、审批、验收和资料确认仍使用对应业务流程；飞书代答另按已授权的绑定与设置运行。跟进草稿由你核对和使用。

## 备份与恢复

主动设置、行动及历史随 schema 13 工作区备份保存，旧版工作区自动迁移。恢复备份保留行动，但暂停主动巡检；核对记录后重新启用，助理再按当前资料评估。暂停状态跨应用重启保留。

## 本地验证

```bash
cargo test -p project-assistant-core
cargo build -p project-assistant-core --bin pm-host
npm run verify:proactive
```

进程验收在 `.local-data/proactive-proof-*` 隔离目录运行真实 Rust `pm-host`，覆盖启动自动扫描、任务变化触发、去重、项目隔离、持续跟进与暂缓的重启持久化、完成后自动收束、关闭巡检、备份恢复暂停和显式重新启用。结果保存在隔离目录的 `verification.json`。

启动验收使用 Python 3 标准库，在 host 停止时仅启用隔离数据库中的巡检设置，再启动进程验证自动发现已有任务。到期复查的时间推进由 Rust 单元测试覆盖；公共接口不接受测试时钟，进程脚本无需等待长周期。全部验收不连接真实模型、飞书账号或外部网络。
