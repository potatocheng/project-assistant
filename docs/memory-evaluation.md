# 记忆系统评估设计

目标：判断系统是否正确记住资料、能否按问题找到当前有效依据，以及最终回答是否有用。分别评估规则可靠性、检索能力和真实模型效果，不将它们合成一个容易误解的“记忆准确率”。

## 评估维度

| 维度 | 要问的问题 | 指标与检查方法 | 本轮覆盖 |
|---|---|---|---|
| 提取正确性 | 事实、负责人、日期、状态有没有提错？原文没有说的是否被补出来？ | 原子事实 precision/recall；负责人、绝对日期、状态逐字段准确率；模糊/相对日期未擅自确定率 | 确定性模型夹具、字段和证据校验；真实 LLM 质量待测 |
| 写入与更新 | 新增、重复、更新、矛盾能否正确处理？纠错后会否继续用旧结论？ | 重复入库率；冲突判断 precision/recall；当前版本使用率；修订原子性和完整历史 | 规则回归、冲突隔离、纠错检查、版本失效；模型语义比较质量待测 |
| 检索召回 | 正确依据是否进入可用上下文？换种说法还能找到吗？ | Recall@1/3/6；模型上下文 Recall@40；每题所需依据全部命中率 | 固定合成问题集，分精确、改写、跨语言、长文、多依据 |
| 排序与干扰 | 正确依据能否排前面？相关但不作答的记录会否挤占上下文？ | MRR@6；候选相关性人工评分；随干扰规模的召回变化 | 固定题集排序；19/119/1019 条项目记忆下固定问题重复计时 |
| 时效与范围 | 旧负责人、旧截止日期、待确认冲突或其他项目是否混入？ | 跨项目泄漏数；旧版本/冲突泄漏数；生成期间修改后的过期回答拒绝率 | 测试中的硬约束：泄漏应为0，过期结果须被拒绝 |
| 无答案与不确定性 | 没有资料时是否明确说明？有相似词能否识别依据不足？ | 无答案题空集合比例；无答案题被标 grounded 比例；真实模型正确拒答率 | 前两项可以离线测；真实模型拒答率待测。模型候选非空本身不算拒答失败 |
| 回答正确与可追溯 | 结论正确吗？每项关键事实有足够引用吗？因果是否过度推断？ | 人工事实正确率；不受支持的断言比例；引用完整率与支持率；多跳问题完整度 | 引用合法性、版本与原文定位已测；真实生成的语义正确性待测 |
| 持久化与可控性 | 重启/备份恢复后是否一致？用户能否修正、清空偏好？派生简报会否过期？ | 重启/恢复一致性；幂等；版本冲突；旧工作迟到写入拒绝；偏好清空与简报失效 | 公共 Engine 集成测试与真实进程脚本 |
| 性能与成本 | 记忆增长后要等多久、发送多少材料、调用几次模型？ | P50/P95 延迟；上下文字符/实际 token；模型请求数与实际费用 | 单机 debug 本地计时与上下文字符；真实端到端延迟/token/费用待测 |
| 纠错闭环 | 能否复现用户指出的问题，定位到资料、版本和规则？ | 纠错样本留存完整性；抽检幂等；同一冻结题集前后差异；修正后的回归率 | 纠错及抽检快照、来源、模型/提示版本和作用域校验 |

## 本轮怎么测

### 1. 工程回归

运行 Rust 核心单元测试及公共 Engine 集成测试，覆盖提取协议与引用、任务字段约束、冲突、当前版本检索、过期模型结果、跨项目隔离、后台任务、旧工作区迁移和备份恢复。新增 schema 8 测试覆盖偏好 CAS/清空/日报格式冻结、简报范围与过期、纠错事务、抽检幂等与来源、重启和恢复。

本地确定性 HTTP 服务返回预先设定的模型输出。这能验证程序如何处理好/坏输出，不能证明真实 LLM 会生成好输出。真实进程脚本使用独立临时目录和假凭据。

### 2. 能力题集

数据文件：`crates/core/tests/fixtures/memory-evaluation-v1.json`。

- 19 条人工编写的基础记忆，含当前版本、旧修订、长正文及1条待确认冲突。
- 120 条干扰记忆、隔离项目记忆和未确认候选。
- 35 道题，其中29道有可用答案，6道无可用答案。
- 类别：精确问法、有限跨语言别名、字符归一化、一般改写、强语义改写、否定表达的依据、最新版本、长文尾部、多条依据、无答案、未确认、冲突。
- 正式记忆直接预置到临时 SQLite，专门隔离检索能力；不经过真实模型提取，也不使用用户工作区。

三个入口分别衡量：

1. `connector_memory`：飞书记忆检索实际返回的最多6条记忆，不调用代答模型。
2. `desktop_local_answer`：桌面本地回答实际引用的记录，指标观察前6条，JSON保留全部引用。
3. `desktop_model_context`：桌面真实模型请求共用的候选选择函数，观察完整的最多40条引用。模型本轮不执行。

模型上下文可用证据与最终回答正确性必须分别看；本地规则回答没有使用某条记忆，不能直接推断模型也看不到它。

## 指标定义

- **Recall@K**：每题前K条中命中的标准依据数量 ÷ 该题所需标准依据数量，再对有答案题取平均。多依据题可以部分得分。
- **全部依据命中率**：前K条包含该题所有标准依据的有答案题占比。用来发现多跳问题材料不全。
- **MRR@6**：第一条正确依据在前6条中的名次取倒数，未命中记0，再对有答案题取平均。
- **无答案题空集合比例**：无可用依据的题中，实际返回0条候选/引用的比例。它描述选择行为，不能代替 LLM 拒答正确率。
- **泄漏**：本次观察记录中出现其他项目、已过期修订或待确认冲突记录。作用域和版本约束作为硬断言。
- **延迟**：主题集测同进程、内存 SQLite 的检索及上下文校验（校验包含再次检索），桌面另含本地回答/候选选择。规模测试只计单次飞书记忆检索；10次相同问题不算10份独立正确率样本。

未计算全局 precision：这批资料只标了每题必要依据，未为所有候选提供分级相关性标签。也未把“含否定词的依据被找回”当成“模型理解了否定”，或把“引用 ID 合法”当成“结论正确”。

## 如何判断是否够好

先设硬门槛，再看质量指标，最后衡量成本。以下是建议用于本项目的初始验收目标，并非行业通用标准或本轮已达成的结论：

| 项目 | 建议初始目标 |
|---|---|
| 项目隔离、当前版本、未确认冲突过滤 | 测试中泄漏0条；任何失败都阻止发布 |
| 修订、重启、备份恢复 | 测试状态和证据一致；过期结果不能写入 |
| 真实常见问题的证据 Recall@6 | 在冻结测试集上争取≥95%；强改写、多依据另列成绩 |
| 真实无答案问题 | 对关键负责人/日期/权限等事实不猜测，单独人工核对拒答 |
| 真实提取 | 事实、负责人、日期分别报告precision/recall与样本数，不给单一总分；关键错误逐条修复 |
| 完整回答 | 与参考答案、允许的等价答案和原文逐项对照；引用应支持关键结论 |
| 延迟与费用 | 先记录当前基线，再约定用户可接受预算；比较同机、同模型、同题集的改进幅度 |

本轮35题是有意包含难题的合成诊断集，不代表生产问题分布。必须同时报告分子/分母，小样本的百分比不可直接外推。

## 下一轮真实模型评估

1. 选取脱敏的代表性项目资料，人工拆出原子事实、负责人、日期、决策及原文位置。模糊日期、未知负责人标为未知，保留允许的等价表达。
2. 准备约100道真实问题作为起步样本，包含精确、改写、多依据、旧事实诱导和无答案；同一项目相似问题成组，避免重复问法冒充独立样本。
3. 分开开发集与冻结测试集。规则和提示只根据开发集调整；保留未见测试集，修改数据集时升版本并记录指纹。
4. 提取评估从原文起步；检索评估从人工标准记忆起步；端到端评估从模型实际提取记忆起步。三者分别报告，才能判断错误出在哪一层。
5. 固定模型、提示版本、服务、参数与检索配置，记录输出、引用、耗时和用量。同一问题可重复执行观察稳定性，不将重复次数当独立样本。
6. 人工评审先按标准答案核对，再记录关键错误；对争议样本复核。LLM 可以辅助评分，不能独自充当金标准。
7. 依次比较当前检索、混合检索、重排和受控多轮搜索。只有在未见样本上稳定改善，且成本可接受，才扩大使用范围。

## 复现

```bash
npm run evaluate:memory
cargo test -p project-assistant-core --locked --no-fail-fast
```

第一条运行真实 Rust 检索代码，生成 `docs/memory-evaluation-results.json` 和可读的 `docs/memory-evaluation-report.md`。测试通过仅保证硬约束，没有把召回不足的样本删掉或强制当成已通过。原始 JSON 保留逐题候选、本地回答和计时，便于后续比较。
