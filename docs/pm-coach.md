# 新手项目推进

保留「今天 / 项目 / 资料」导航，在具体任务内提供帮助。

- 首页今日工作旁点击「帮我推进」，或在任务详情、提醒与跟进详情打开引导。
- 任务标题、说明中的内置术语可以直接点击。解释包含白话定义、通用例子和可采取的行动；例子不作为项目事实。关键节点标题也提供里程碑解释。
- 卡点使用五种现象：等别人回复、没说清怎样算做好、缺人手或条件、等人拍板、我也不确定。每种给出一个关键问题、行动建议和可编辑沟通草稿。「为什么」按需展开。草稿由用户复制使用。
- 「记录跟进结果」默认只需一句实际情况。结果默认“先记下情况”，可安排下次跟进；人员、对方承诺日期和发生日期在补充区域内。
- 明确选择“有了实际进展 / 仍有问题卡住 / 已交付并确认完成”后，任务分别更新为进行中 / 阻塞 / 完成。保存前显示将发生的变化。完成时进度设为 100%，清除后续跟进；其他结果保留进度。

引导、术语和结果记录均为本地能力，无需模型或外发资料。草稿不会进入项目事实。没有答复只表示需要核实原因；承诺日期不覆盖任务截止日期。实际权限、资源和方案取舍仍由相应人员确认。

## 保存与兼容

复用 SQLite 的 `task_follow_ups`、`task_follow_up_state` 和任务事件，无需数据库迁移。`record_follow_up` 新增可选 `taskOutcome: { baseVersion, status }`，旧调用保持原语义。任务版本与跟进版本均校验，任务状态、任务事件和跟进记录使用同一事务；任一步失败全部回滚。

引导和结果草稿分别使用 `task:coach:<id>`、`task:follow-result:<id>`，沿用本机草稿、版本检查及备份恢复。记录在任务详情内折叠展示，也进入现有跟进、提醒及项目问答数据范围。选择会改变任务状态的结果时，同样生成任务事件供日报回看。

对话框挂载到应用外壳内，与其他对话框并列，保留主题并避免受到父对话框变换和裁切的影响。仅最前面的对话框响应 Escape 和焦点循环。

```powershell
npm run verify:coach
npm run verify:workbench
npm run build
cargo test -p project-assistant-core --test delivery_engine
cargo clippy -p project-assistant-core --lib --tests -- -D warnings
```

引擎回归覆盖承诺保持原任务状态、显式结果写入两类历史、完成后的提醒结束、任务或跟进版本冲突回滚、发生日期校验及重启后持久化。隔离工作区的浏览器验证覆盖术语解释、卡点切换、嵌套对话框 Escape、结果保存、刷新回看、明确完成和窄屏显示。
